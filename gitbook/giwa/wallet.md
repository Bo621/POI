# 월렛 탑재 가능성

> 아래는 검증 완료된 탑재가 아니라 **탑재 후보 구조**입니다. 실제 GIWA 월렛 안에서
> 동작하는지는 아직 검증되지 않았습니다.

## 왜 후보 구조로 검토할 수 있는가

현재 구현에서 확인되는 사실은 다음과 같습니다.

* 별도 백엔드 없이 정적 파일과 RPC 직접 호출로 동작합니다.
* 라우터 라이브러리 없이 해시 라우팅 `#/d/<uid>`를 사용합니다.
* 지갑 연동에 요구하는 인터페이스는 EIP-1193입니다.
* 조회와 검증은 지갑 연결 없이 동작합니다.
* 결정 트랜잭션은 건당 **1.21원**(실측)이며 서명은 1회입니다.

## 월렛 안에서의 흐름

다음 흐름을 가정할 수 있습니다.

```
내 판단 기록 → 결정 커밋 → 결과 등록
```

## 확인이 필요한 것

* 월렛은 웹 콘텐츠를 어떤 방식으로 임베드하는가?
* 해시 라우팅이나 새로고침에 제약이 있는가?
* EIP-1193 서명 UX는 외부 브라우저와 어떻게 다른가?
* 결정 상세로 연결하는 딥링크 규격은 무엇인가?

이 질문들이 확인되기 전에는 월렛 탑재 가능성을 구현 완료로 서술하지 않습니다.
