# 보안 모델

> 무엇을 막고, 무엇을 막지 못하며, 무엇이 깨지면 제품이 무너지는가.

## 위협 주체와 대응

| 공격 | 무엇을 노리는가 | 대응 | 강도 |
|---|---|---|---|
| **사후 서사** | 결과를 본 뒤 판단을 소급 기록 | `windowStart >= 커밋 시각` (I4) | **컨트랙트 강제** |
| **거짓 정산** | 관측값과 모순되는 결과 기록 | 컨트랙트가 `result` 재계산·대조 (I17) | **컨트랙트 강제** |
| **기준 바꾸기** | 나중에 유리하게 지표 정의 변경 | 문서 바이트 해시가 온체인, 등록 즉시 `frozen` | **컨트랙트 강제** |
| **관측 시점 고르기** | 유리한 순간의 값을 제출 | `observedAt == windowEnd` (I8) | **컨트랙트 강제** |
| **복사 공격 (CT18)** | 남의 commitment를 자기 것으로 | 프리이미지에 attester 포함 | **컨트랙트·검증기** |
| **남의 계보 훔치기** | 타인 결정을 자기 부모로 | `parent.attester == attester` (I3) | **컨트랙트 강제** |
| **비정규 payload** | 잉여 워드로 이상한 바이트 영구 기록 | 디코딩 후 재인코딩해 바이트 대조 | **컨트랙트 강제** |
| **그리핑** | 남의 결정에 임의 정산 선점 | 정산 권한을 소유자로 제한 | **컨트랙트 강제** |
| **Sybil 이의** | 다수 지갑으로 이의를 부풀려 신뢰 훼손 | **건수를 표시하지 않음.** 목록과 검증 지갑 여부만 | 설계 |
| **선택적 기록** | 좋은 판단만 남기기 | 미발행을 「기한초과」로 노출. 랭킹 금지 | **부분적** |
| **거짓 관측값** | 사실과 다른 값을 제출 | 제3자 재현 + 이의 | **약함 — Phase 2 오라클** |

## 신뢰 가정

이것들이 깨지면 POI의 주장도 함께 무너집니다.

1. **keccak256 충돌 저항성** — commitment 구속의 전제
2. **EAS 프리디플로이가 정직하게 동작** — 우리 리졸버를 실제로 호출한다
   *(포크 테스트가 실제 바이트코드 상대로 이를 확인한다)*
3. **체인 시각이 조작되지 않음** — 모든 시점 불변식이 `block.timestamp` 기반
4. **업비트 공개 API가 과거 데이터를 바꾸지 않음** — 재현의 전제
5. **RPC 노드가 정직하게 응답** — 조회 결과의 전제

## 사용자 측 위험

| | |
|---|---|
| **salt 유실** | 공개(Reveal)가 **영구 불가**해집니다. 커밋은 남지만 내용을 증명할 수 없습니다. 그래서 발행 전에 salt 백업 확인을 강제합니다 |
| **키 유실** | 그 지갑의 결정에 결과를 등록할 수 없습니다 → 전부 「기한초과」가 됩니다 |
| **잘못된 지표 선택** | 등록 후 `frozen`이라 결정 자체를 새로 커밋해야 합니다 |

## 운영 측 위험 — 지금 열려 있는 것

**`POIDecisionResolver`의 owner가 아직 배포 지갑입니다.**

owner가 할 수 있는 것은 `addMetric`뿐이고, **이미 등록된 지표는 `frozen`이라 바꿀 수
없습니다.** 그래도 키가 탈취되면 임의 지표를 추가할 수 있으므로 multisig로 옮겨야 합니다.

`renounce`는 하지 않습니다 — Phase 1에서 지표를 추가해야 합니다.

## 조회 완전성

**조회된 것이 전부라는 보장이 없습니다.** RPC 인덱싱 범위와 노드 상태에 따라
목록이 달라질 수 있습니다. 그래서 모든 목록에 그 사실을 표시하고 **건수를 세지 않습니다.**

건수를 세는 순간 "조회된 것이 전부"라는 거짓 전제가 들어갑니다.
