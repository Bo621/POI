## 지금 어디까지 검증되나

POI 가 검증하는 것을 세 층으로 나누면 **두 층까지 와 있습니다.**

| 층 | 무엇 | 지금 | 무엇으로 |
|---|---|---|---|
| ① **말한 것** | 결정 커밋 | ✅ 검증됨 | commitment · 관측 구간 선언 · `I4` |
| ② **본 것** | 관측·정산 | ✅ 검증됨 | 지표 해시 `frozen` · `I17` 산술 강제 |
| ③ **한 것** | 실제 체결 | ❌ **비어 있다** | — |

③ 이 비어 있다는 것은 이미 두 곳에 적혀 있습니다 —
[신뢰 경계](../problem/trust-boundary.md)의 「실제 거래와의 정합성: 보장하지 않음」과
[배포 상태표](status.md)의 「실행 정합성 ❌」입니다.

**로드맵의 중심은 ③ 을 채우는 것입니다.**

## 왜 이 순서인가

각 단계가 **무엇에 기대는지**를 적습니다.

### 1단계 (8월) — 자체 구현. 막는 것이 없다

지표 화이트리스트 확대, 공개 범위 제어, up.id 크로스체인 해석.

외부 의존이 없어 먼저 합니다. **지표가 2종뿐인 것이 지금 가장 큰 실용적 제약**이라
여기가 첫 순서입니다.

### 2단계 (9월) — ③ 을 채운다. 외부 의존이 시작된다

| 항목 | 무엇이 열리나 | 막고 있는 것 |
|---|---|---|
| Execution 경로 | 「말한 대로 했나」. 체결 내역과 결정을 대조한다 | **거래소 Open API 읽기 권한** — 지금 쓰는 것은 업비트 *공개 시세* API 뿐이고 개인 거래내역 접근 권한이 없습니다 |
| `ORACLE_VERIFIED` | 관측값을 제3자가 독립 증명. 신뢰 경계가 「소유자 제출」에서 「독립 판정」으로 넘어간다 | **Upbit Oracle 사양·일정** |
| Verified Balance 배지 | 잔고를 밝히지 않고 보유를 증명 | **도장 스냅샷 발급 주기** — 주기를 몰라 관측 해상도를 특정할 수 없습니다 |

**Execution 경로가 왜 중요한가** — [누가 쓰는가](../problem/who.md)에서 답하지 못한
「한 지갑 안에서의 선택적 기록」이 여기서 좁혀집니다. 거래가 있었는데 대응하는 결정이
없으면 **그 공백도 드러나기** 때문입니다.

> **이것은 가설입니다.** 거래소가 읽기 권한을 열지, 개인정보를 어떻게 분리할지,
> 어느 범위까지 온체인에 남길지 — 아무것도 확정되지 않았습니다.

### 3단계 (10월) — 밖에서 읽을 수 있게 한다

외부 조회 API. 다른 제품이 POI 의 검증 결과를 읽어 쓸 수 있게 하는 단계입니다.
자체 구현이라 막는 것이 없지만, **2단계가 없으면 읽을 값이 얕습니다.**

### 4단계 (11월) — 감사와 검증

**외부 보안 감사.** 지금까지는 내부 테스트와 교차 리뷰뿐입니다([팀](../team.md)).
자산을 직접 다루지는 않지만 신원 스냅샷과 되돌릴 수 없는 기록을 다루므로, 메인넷
공개 전에 외부 감사가 필요하다고 봅니다. **감사 범위·기관·예산은 아직 정하지
않았습니다** — 1단계에서 정합니다.

**실사용자 검증 실험.** [누가 쓰는가](../problem/who.md)의 30일 실험을 돌립니다 —
사용자 10명이 각 3건 이상, 합쳐 30건을 커밋하고 그중 15건 이상이 결과 등록되는가.
**이 제품에서 가장 검증되지 않은 부분입니다.**

### 5단계 (12월) — 출시 판단

감사 조치가 끝나고 실험 기준을 넘으면 공개 메인넷에 올립니다.
**미달이면 올리지 않습니다.** 등록률이 낮다는 것은 「미발행 노출」이 사용자에게
이득이 아니라 위협으로 작동한다는 뜻이고, 그러면 설계를 다시 봐야 합니다.

### 이후 — 프라이버시

ZK 술어. 결정의 predicate 가 `metricId · op · threshold` 구조라
**ZK 술어와 같은 모양**입니다. 그래서 스키마를 바꾸지 않고 적용할 수 있으리라 봅니다.

막고 있는 것: **보자기 개발자 문서.** 공개되면 검토합니다.

## 그 위에 무엇이 올라갈 수 있나

검증된 판단이 쌓이면 그 위에 제품이 올라갑니다.
아래 넷은 **배포된 컨트랙트를 읽기만 하면 되는 것들**이라 새 온체인 구조가 필요하지
않다는 뜻이지, **만들었다는 뜻이 아닙니다. 전부 미구현입니다.**

| | 무엇 | 무엇으로 되나 |
|---|---|---|
| 검증된 판단 피드 | 스크린샷·평판 대신 온체인 정산 결과가 흐른다 | 결정 로그 조회 + 상태 판정 |
| 조건부 열람 | 「`MATCH` N건 이상」인 사람만 보는 방 | 온체인 정산 결과로 필터 |
| 보유 증명 커뮤니티 | 잔고를 밝히지 않고 자격만 증명 | 도장 Verified Balance 머클 증명 |
| B2B 신뢰도 부착 | 리서치 발행물에 검증 링크 | 외부 조회 API (3단계) |

## 무엇이 이 로드맵을 무너뜨리나

| | |
|---|---|
| 사람들이 판단을 반복해서 남기지 않으면 | 1단계 이후가 전부 의미가 없습니다. 이것이 [첫 검증 대상](../problem/who.md)입니다 |
| 거래소 권한이 안 열리면 | ③ 이 계속 비어 있습니다. 「말한 것」까지만 증명하는 제품으로 남습니다 |
| 오라클이 안 나오면 | 관측값은 계속 소유자 제출입니다. 재현 가능성과 이의로만 다룹니다 |

**1단계 이후 항목은 현재 구현됐다고 주장하지 않습니다.** 전부 계획입니다.
