## 지금 어디까지 검증되나

POI 가 검증하는 것을 세 층으로 나누면 **두 층까지 와 있습니다.**

| 층 | 무엇 | 지금 | 무엇으로 |
|---|---|---|---|
| ① **말한 것** | 결정 커밋 | ✅ 검증됨 | commitment · 관측 구간 선언 · `I4` |
| ② **본 것** | 관측·정산 | ✅ 검증됨 | 지표 해시 `frozen` · `I17` 산술 강제 |
| ③ **한 것** | 실제 체결 | ❌ **비어 있다** | — |

③ 이 비어 있다는 것은 이미 두 곳에 적혀 있습니다 —
[신뢰 경계](../problem/trust-boundary.md)의 「실제 거래와의 정합성: 보장하지 않음」과
[배포 상태표](status.md)의 「실행 정합성 ❌」입니다.

**로드맵의 중심은 ③ 을 채우는 것입니다.**

## 왜 이 순서인가

각 단계가 **무엇에 기대는지**를 적습니다.

### 1단계 (8월) — 자체 구현. 막는 것이 없다

지표 화이트리스트 확대, 공개 범위 제어, up.id 크로스체인 해석.

외부 의존이 없어 먼저 합니다. **지표가 2종뿐인 것이 지금 가장 큰 실용적 제약**이라
여기가 첫 순서입니다.

### 2단계 (9월) — ③ 을 채운다. 외부 의존이 시작된다

| 항목 | 무엇이 열리나 | 막고 있는 것 |
|---|---|---|
| Execution 경로 | 「말한 대로 했나」. 체결 내역과 결정을 대조한다 | **거래소 Open API 읽기 권한** — 지금 쓰는 것은 업비트 *공개 시세* API 뿐이고 개인 거래내역 접근 권한이 없습니다 |
| `ORACLE_VERIFIED` | 관측값을 제3자가 독립 증명. 신뢰 경계가 「소유자 제출」에서 「독립 판정」으로 넘어간다 | **Upbit Oracle 사양·일정** |
| Verified Balance 배지 | 「그때 무엇을 들고 있었나」를 발행자 검증으로 붙인다 (**잔고 값은 공개된다**) | **도장 스냅샷 발급 주기** — 주기를 몰라 관측 해상도를 특정할 수 없습니다 |

**Execution 경로가 왜 중요한가** — [누가 쓰는가](../problem/who.md)에서 답하지 못한
「한 지갑 안에서의 선택적 기록」이 여기서 좁혀집니다. 거래가 있었는데 대응하는 결정이
없으면 **그 공백도 드러나기** 때문입니다.

> **이것은 가설입니다.** 거래소가 읽기 권한을 열지, 개인정보를 어떻게 분리할지,
> 어느 범위까지 온체인에 남길지 — 아무것도 확정되지 않았습니다.

### 3단계 (10월) — 밖에서 읽을 수 있게 한다

외부 조회 API. 다른 제품이 POI 의 검증 결과를 읽어 쓸 수 있게 하는 단계입니다.
자체 구현이라 막는 것이 없지만, **2단계가 없으면 읽을 값이 얕습니다.**

### 4단계 (11월) — 감사와 검증

**외부 보안 감사.** 지금까지는 내부 테스트와 교차 리뷰뿐입니다([팀](../team.md)).
자산을 직접 다루지는 않지만 신원 스냅샷과 되돌릴 수 없는 기록을 다루므로, 메인넷
공개 전에 외부 감사가 필요하다고 봅니다. **감사 범위·기관·예산은 아직 정하지
않았습니다** — 1단계에서 정합니다.

**실사용자 검증 실험.** [누가 쓰는가](../problem/who.md)의 30일 실험을 돌립니다 —
사용자 10명이 각 3건 이상, 합쳐 30건을 커밋하고 그중 15건 이상이 결과 등록되는가.
**이 제품에서 가장 검증되지 않은 부분입니다.**

### 5단계 (12월) — 출시 판단

감사 조치가 끝나고 실험 기준을 넘으면 공개 메인넷에 올립니다.
**미달이면 올리지 않습니다.** 등록률이 낮다는 것은 「미발행 노출」이 사용자에게
이득이 아니라 위협으로 작동한다는 뜻이고, 그러면 설계를 다시 봐야 합니다.

### 이후 — ZK 술어 (보자기)

지금 구조에는 딜레마가 하나 있습니다. **예상 결과를 선언해야** 컨트랙트 판정(`I17`)과
기한초과 노출이 작동하는데, **선언하는 순간 조건이 공개**됩니다 —
`outcomeMetricId · outcomeOp · outcomeThreshold` 는 평문 필드입니다.
선언하지 않으면(`hasExpectedOutcome=false`) 조건은 숨지만 판정도 미발행 노출도
함께 꺼집니다(`I6d`).

**유료 리서치를 파는 사람에게 이건 실제 장벽입니다** — 발행 전에 커밋하면
구독자가 돈 내고 볼 판단의 뼈대를 온체인에서 먼저 읽습니다
([첫 사용자](../problem/who.md)가 정확히 이 사람입니다).

| 항목 | 무엇이 열리나 | 막고 있는 것 |
|---|---|---|
| 술어 은닉 커밋 | 구간은 평문으로 두고 **술어 셋만 커밋**합니다. 전략을 밝히지 않고 사전 고정하는 길이 열립니다 | 보자기 문서 · **증명 검증 경로 설계** |
| 잔고 조건 증명 | 도장 Verified Balance 는 잔고 값을 공개합니다. `balance ≥ X` 만 증명하려면 ZK 가 필요합니다 | 위와 같음 |
| 완전성 부분 증명 | 「이 구간 거래 N건 중 사전 결정이 있는 것이 M건」. [신뢰 경계](../problem/trust-boundary.md)의 「기록의 완전성」을 다루는 경로입니다 | 위 + 거래소 권한(2단계) + **거래소가 서명한 거래집합** |

**기한초과 노출은 살아남습니다.** 상태 판정(`PENDING · OBSERVING · AWAITING · OVERDUE`)은
`windowStart · windowEnd · graceSeconds` 만 보고 술어는 보지 않습니다 (`core/src/state.ts`).
그래서 술어만 숨겨도 「말해놓고 결과가 나쁘면 정산을 안 낸다」를 막는 장치는 그대로입니다.

#### 정직하게 적어 두는 것

**스키마만 그대로 두면 되는 일이 아닙니다.** 지금 리졸버는 평문 `op · threshold` 로
`I17` 산술을 직접 계산합니다. 술어를 숨기면 그 산술을 **증명 검증으로 대체**해야 하고,
POI 에는 아직 그 경로가 없습니다. 기존 필드에 증명 해시를 넣는 것만으로는
아무것도 검증되지 않습니다. 가스 비용도 아직 모릅니다.

**ZK 가 없으면 못 하는 것은 아닙니다.** 완전성은 지정된 검증자가 거래내역을
오프체인에서 대조하고 집계 결과만 발행하는 방식으로도 됩니다. 다만 그러면
**그 검증자를 믿어야** 합니다. ZK 가 없애는 것은 기능의 불가능이 아니라
**믿어야 할 대상**입니다.

**ZK 도 만능이 아닙니다.** 증명은 주어진 데이터에 대한 계산이 옳다는 것만 보입니다.
사용자가 애초에 거래 일부를 빼고 넣었는지는 증명이 알 수 없습니다.
완전성이 성립하려면 **거래소가 서명한 완전한 거래집합**이 먼저 있어야 합니다.

**신뢰 경계는 ZK 가 옮기지 않습니다.** 술어를 숨겨도 관측값은 여전히 발행자 제출입니다.
그것을 옮기는 것은 `ORACLE_VERIFIED`(2단계) 쪽입니다.

**무엇으로 끝났다고 하는가** — 같은 fixture 를 평문 경로와 증명 경로로 각각 발행해
판정이 일치하는 것을 확인합니다.

## 그 위에 무엇이 올라갈 수 있나

검증된 판단이 쌓이면 그 위에 제품이 올라갑니다.
아래 넷은 **배포된 컨트랙트를 읽기만 하면 되는 것들**이라 새 온체인 구조가 필요하지
않다는 뜻이지, **만들었다는 뜻이 아닙니다. 전부 미구현입니다.**

| | 무엇 | 무엇으로 되나 |
|---|---|---|
| 검증된 판단 피드 | 스크린샷·평판 대신 온체인 정산 결과가 흐른다 | 결정 로그 조회 + 상태 판정 |
| 조건부 열람 | 「`MATCH` N건 이상」인 사람만 보는 방 | 온체인 정산 결과로 필터 |
| 보유 증명 커뮤니티 | 검증된 보유량으로 자격을 가른다. **잔고를 숨기려면 ZK 가 필요하다** | 도장 Verified Balance 머클 증명 |
| B2B 신뢰도 부착 | 리서치 발행물에 검증 링크 | 외부 조회 API (3단계) |

## 무엇이 이 로드맵을 무너뜨리나

| | |
|---|---|
| 사람들이 판단을 반복해서 남기지 않으면 | 1단계 이후가 전부 의미가 없습니다. 이것이 [첫 검증 대상](../problem/who.md)입니다 |
| 거래소 권한이 안 열리면 | ③ 이 계속 비어 있습니다. 「말한 것」까지만 증명하는 제품으로 남습니다 |
| 오라클이 안 나오면 | 관측값은 계속 소유자 제출입니다. 재현 가능성과 이의로만 다룹니다 |

**1단계 이후 항목은 현재 구현됐다고 주장하지 않습니다.** 전부 계획입니다.
