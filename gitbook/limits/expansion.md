# 확장 경로 — 같은 구조로 무엇을 더 증명할 수 있나

> **여기 적힌 것은 전부 미구현입니다.** [로드맵](roadmap.md)의 5단계까지가 실제 계획이고,
> 이 문서는 그 다음에 열리는 방향입니다. 규제 일정과 외부 기술에 걸려 있어
> **시점을 약속하지 않습니다.**

---

## 하나의 구조, 여러 명제

POI 가 지금 하는 일은 한 문장으로 줄어듭니다.

```
어떤 명제를 결과가 나오기 전에 고정하고,
나중에 제3자가 그 고정을 확인한다.
```

지금 그 명제는 **「이 판단이 언제 있었고 무엇을 말했는가」** 하나입니다.
그런데 고정하고 확인하는 구조 자체는 명제를 가리지 않습니다.

| 명제 | 지금 | 확장 |
|---|---|---|
| 이 판단을 그때 했다 | ✅ 구현 | — |
| 나는 이 자격 요건을 충족한다 | ❌ | 적격투자자 증명 |
| 나는 이만큼의 자금을 동원할 수 있다 | ❌ | 자금 보유 증명 |
| 내 자금은 출처 확인을 통과했다 | ❌ | AML 상태 증명 |
| 내 투자 이력은 이 조건을 만족한다 | ❌ | 성과 증명 |

전부 **「값을 다 보여주지 않고 조건이 참임을 보인다」** 입니다.
POI 의 술어(`지표 · 부등호 · 기준값`)가 이미 그 모양이고,
[ZK 술어](roadmap.md)가 붙으면 값을 숨긴 채로도 같은 일을 할 수 있습니다.

---

## 왜 지금 이 방향을 적는가 — 규제 일정

두 법의 상태가 정반대라서, 붙일 수 있는 것과 없는 것이 갈립니다.

| | 상태 | POI 에 뜻하는 것 |
|---|---|---|
| **토큰증권** | 전자증권법·자본시장법 개정안 **2026-01-15 국회 본회의 통과** · 전자증권법 **2027-02-04 시행** | 시점이 정해져 있다. 2026 년에 PoC, 2027 년 시행에 맞춰 붙인다 |
| **원화 스테이블코인** | 디지털자산기본법 **아직 제정 안 됨.** 발행 주체(은행 51%룰) **미합의** | 시점을 못 정한다. 발행 주체가 되려 하지 않고 **붙는 쪽**으로 남는다 |

> **출처** — [토큰증권 개정법 공포·시행 예정 (김·장)](https://www.kimchang.com/ko/insights/detail.kc?sch_section=4&idx=34390) ·
> [디지털자산기본법 연내 추진 (블록미디어)](https://www.blockmedia.co.kr/archives/1117098)

**그래서 POI 는 스테이블코인을 발행하지 않습니다.** 은행·증권사·거래소가 발행한 것에
**증명을 붙이는 쪽**이 규제상으로도 현실적이고, POI 가 이미 하고 있는 일과도 같습니다.

## 보자기 — 이미 실증된 기술이다

이 확장의 열쇠는 [ZK 술어](roadmap.md)이고, 그 수단이 GIWA 의 **보자기**입니다.
그리고 보자기는 아이디어 단계가 아닙니다.

```
2026-02-27   두나무 × 하나금융그룹 해외송금 PoC 완료
             하나은행 국내·해외 지점 간 SWIFT 전문을 기와체인 메시지로 대체
             송금인·수취인 정보 보호에 보자기(ZKP) 사용
```

> **출처** — [두나무 공식 발표](https://www.dunamu.com/news/1651)

**막고 있는 것은 기술이 아니라 개발자 문서입니다.**
`docs.giwa.io/giwa-ecosystem/bojagi` 는 아직 404 이고 생태계 목록에도 없습니다 (2026-07-30 확인).
은행 PoC 에 쓸 만큼 돌아가는 기술이 있는데 바깥에서 붙일 방법이 없습니다.
[GASOK 에 요청하는 것](roadmap.md)이 이것입니다.

### 보자기와 POI 는 겹치지 않는다

| | 무엇을 가리나 |
|---|---|
| 보자기 | **거래 자체**의 프라이버시 — 송금인·수취인·금액 |
| POI | **거래 주체**의 자격·이력 — 값을 숨긴 채 조건 충족만 |

같은 지갑으로 「누가 보냈는지 모르게」와 「보낼 자격이 있다는 것은 증명하며」를
동시에 할 수 있습니다. 경쟁이 아니라 결합입니다.

## 확장 후보 — 무엇이 열리고 무엇에 걸려 있나

우선순위 순입니다. 위에서부터 지금 구조와 가깝습니다.

| | 무엇을 증명하나 | 지금 구조에서 얼마나 먼가 | 막고 있는 것 |
|---|---|---|---|
| **① 성과 증명** | 「12 개월 이상 · 누적 수익률 X% 이상 · 최대 낙폭 Y% 이하」를 원금과 거래내역 없이 | **가깝다.** 이미 결정·정산·이의가 있고 [실행 정합성](roadmap.md)이 2단계다 | 거래소 API 권한 · ZK 술어 |
| **② 자금 보유 증명** | 「적격 자금 N 원 이상 보유」를 잔액과 계좌 없이 | **중간.** 도장 Verified Balance 가 있으나 [잔고 값이 공개](../giwa/wallet.md)돼 ZK 가 필요하다 | ZK 술어 · 발급기관 협의 |
| **③ 적격투자자 증명** | 「이 상품의 투자자 요건을 충족」을 자산 규모 없이 | **중간.** 발급 주체가 금융기관이라 POI 는 검증 레이어만 맡는다 | 하위법규(2027) · 금융기관 제휴 |
| **④ 투자한도 통합 증명** | 「전 플랫폼 합산 투자액이 연간 한도 이내」를 각 플랫폼 금액 없이 | **멀다.** 여러 발급자를 가로질러 합산해야 한다 | 위 전부 + 플랫폼 간 표준 |
| **⑤ 보유·현금흐름 증명** | 「이 RWA 를 N개월 이상 보유」 「담보로 중복 설정돼 있지 않다」 를 포트폴리오 없이 | **멀다.** RWA 가 실제로 발행돼야 대상이 생긴다 | 토큰증권 시행(2027) + 발행사 제휴 |

**①이 첫 번째인 이유** — POI 가 이미 하고 있는 일의 연장이기 때문입니다.
지금은 「이 판단을 그때 했다」까지고, 거래소를 붙이면 「말한 대로 했다」가 되고,
ZK 가 붙으면 「원금을 밝히지 않고 성과를 증명한다」가 됩니다.
②③④는 새 파트너가 필요하지만 ①은 **로드맵 2단계의 자연스러운 다음 칸**입니다.

## 어디에 무엇을 올리나 — 지금과 같은 구조입니다

확장해도 온체인에 올리는 것은 늘어나지 않습니다. POI 가 지금 지키는 원칙 그대로입니다.

| | 온체인 | 온체인 밖 |
|---|---|---|
| **지금** | commitment 4종 · 관측 조건·구간 · 정산 결과 · 이의 | 결정 원문 · 이유 · 근거 |
| **확장 후** | 증명 식별자 · 발급기관 · 증명 유형 · 유효기간 · 폐기 여부 · 검증용 commitment | 실명 · 계좌번호 · 정확한 잔액 · 거래내역 · KYC 원본 |

```
데이터 제공자        거래소 · 은행 · 증권사 · RWA 발행사
     ↓
증명 발급            데이터 정규화 → 조건 판정 → attestation 발행
     ↓                (POI 가 지금 결정·정산에 하는 일과 같습니다)
GIWA                증명 해시 · 발급자 · 유효기간 · 폐기 상태
     ↓
증명 소비            RWA 청약 · 결제 · 심사에서 검증만 하고 통과시킨다
```

**새로 필요한 것은 하나입니다 — `nullifier`.** 같은 증명을 여러 곳에서 중복으로
쓰지 못하게 막는 값입니다. 지금 POI 는 결정마다 UID 가 하나뿐이라 이 문제가 없지만,
「자격 증명」은 한 번 받아 여러 플랫폼에 내는 것이 목적이라 필요해집니다.

## AML — 익명 서비스가 아닙니다

금융에서 쓰이려면 **평상시 비공개, 적법한 요청 시 제한적 공개**여야 합니다.
완전 익명은 규제를 통과하지 못하고, 통과하지 못하는 증명은 쓰이지 않습니다.

발급은 POI 가 하지 않습니다. 은행·거래소·신원확인 사업자가 확인하고 발행하며,
POI 는 **그 증명을 검증하는 층**만 맡습니다.

| 소비자가 보는 것 | 소비자가 못 보는 것 |
|---|---|
| `KYC 완료 = true` · 발급기관 · 유효기간 · 폐기 여부 | 실명 · 주민등록번호 · 거래내역 · 원본 서류 |

RWA 발행사는 사용자의 거래내역 전체를 받는 대신 이 네 줄만 확인하면 됩니다.
**개인정보를 보관하지 않으니 보관 책임도 지지 않습니다.**

## 스테이블코인 결제와 만나는 지점

GIWA 는 **페이마스터**로 수수료를 원화·엔·대만달러 연동 스테이블코인으로 낼 수 있게
설계돼 있고, 도장과 함께 이를 체인의 핵심 기술로 내세우고 있습니다.

> **출처** — [두나무, 자체 블록체인으로 스테이블코인 승부수 (더벨)](https://www.thebell.co.kr/free/content/ArticleView.asp?key=202509090957074200101057)

결제가 열리면 POI 가 붙을 자리가 생깁니다.

| | 지금 | POI 가 붙으면 |
|---|---|---|
| 결제 | 가맹점이 결제자 정보를 받아야 한다 | 「성인 · 국내 거주 · 한도 이내」만 확인하고 통과 |
| RWA 청약 | 플랫폼마다 신분증·자산증명서를 다시 낸다 | 증명 하나로 자격·자금·한도를 한 번에 |

**보자기와 겹치지 않습니다.** 보자기가 「누가 얼마를 보냈는지」를 가리고,
POI 가 「보낼 자격이 있는지」를 증명합니다. 한 결제에서 둘 다 필요합니다.

## 더 멀리 — 지금은 적기만 합니다

| | 왜 지금이 아닌가 |
|---|---|
| RWA 담보대출 | 대부업·여신전문금융업이 걸립니다. POI 가 직접 대출하지 않고 **증명·평가 인프라만** 제공하는 B2B 형태여야 합니다 |
| 국경 간 투자자 증명 | 국가별 증권법·외환법·개인정보보호법을 전부 봐야 합니다. 사업 가치는 가장 크지만 가장 뒤입니다 |

## 수익 구조가 달라지는 지점

지금 [사업 가설](roadmap.md)은 B2C 구독과 검증 수수료입니다.
확장 경로에서는 **증명을 소비하는 쪽이 돈을 냅니다.**

```
지금        판단을 남기는 사람이 낸다        (검증 안 됨)
확장 후     증명을 확인하는 기관이 낸다      B2B 검증 API
```

RWA 발행사·증권사는 투자자마다 서류를 다시 받는 대신 증명 하나를 검증하면 됩니다.
개인정보를 직접 보관하지 않아도 되므로 보안·규제 비용이 줄어듭니다.
**이쪽이 더 그럴듯하지만, 지금은 근거가 없어 가설로만 적습니다.**

## 확장해도 하지 않는 것

[POI 가 하지 않는 것](../README.md)에 이 줄들이 더 붙습니다.

```
자산을 직접 보관하지 않는다          스테이블코인을 직접 발행하지 않는다
RWA 토큰을 직접 발행하지 않는다      투자자를 모아 공동 운용하지 않는다
자동 운용·자동 대출을 하지 않는다     상품을 추천하지 않는다
```

그리고 하나 더 — **익명성을 이유로 AML 확인을 우회하지 않습니다.**
완전 익명은 금융에서 쓰일 수 없고, 쓰이지 못하는 증명은 증명이 아닙니다.
