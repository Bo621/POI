# 하지 못한 것

> 약점을 숨기면 심사자가 대신 찾아냅니다. 그리고 **검증 가능성을 파는 제품이
> 자기 한계에 대해 부정확하면 그 자체가 반증입니다.**

## 외부가 막고 있는 것

의지나 시간의 문제가 아니라, 붙일 대상이 아직 없습니다.

| | 막는 것 | 대안 |
|---|---|---|
| **ZK 프라이버시** | 보자기(Bojagi) 개발자 문서에 페이지 없음 | salted commitment + 구간형 노출. `predicate` 형태가 ZK 술어와 구조적으로 유사해 문서 공개 시 적용 검토 |
| **`ORACLE_VERIFIED`** | Upbit Oracle 제공 데이터 미공개 | 공개 데이터로 정산하고 재현 가능성 + 이의로 대체 |
| **Verified Balance 배지** | 도장 스냅샷 발급 주기 미확인 → 관측 해상도를 특정 못 함 | Phase 2 |
| **up.id 온체인 해석** | GIWA에 미배포 | Verified Address가 신원 역할을 대신함 |

**미공개 사양에 의존하는 기능을 넣으면 "검증 가능하다"는 주장 자체가 거짓이 됩니다.**
그래서 넣지 않았습니다.

## 설계상 지금 없는 것

**독립 판정이 아닙니다.** MVP에서 정산은 **결정 소유자가 발행**합니다. 컨트랙트가
산술은 강제하지만(I17), *관측값 자체*가 참인지는 강제하지 못합니다.
제3자는 재현하고 이의를 남길 수 있을 뿐입니다. 진짜 독립 판정은 오라클(Phase 2)입니다.

> 이것을 "탈중앙 검증"이라고 부르지 않습니다. 지금 있는 것은
> **재현 가능성 + 이의 가능성**이고, 그 이상을 주장하지 않습니다.

**`trigger_predicate`는 온체인 강제가 없습니다.** commitment 뒤에 있어서 컨트랙트가
내용을 볼 수 없습니다. `expected_outcome_predicate`만 지표 화이트리스트가 강제됩니다.
이 비대칭은 의도된 것이고 화면과 문서에 명시합니다.

**결정과 실제 행동의 정합성은 검증하지 않습니다.** "이렇게 판단했다"와 "실제로 그렇게
거래했다"는 다릅니다. 후자는 Phase 2 이후입니다. 실행 정합성 배지를 제공하지 않습니다.

**지표가 2종뿐입니다.** 지표마다 계산식·출처·결측치 정책 문서가 필요하고 그 해시가
온체인에 고정되므로, 문서 없이 늘릴 수 없습니다. append-only라 Phase 1에서 추가됩니다.

**노트 승격의 내용 동일성은 보장되지 않습니다.** 노트를 결정으로 승격할 때
같은 지갑임은 컨트랙트가 강제하지만, 노트 내용과 결정 내용이 같다는 보장은 없습니다.

**배지를 발급하지 않습니다.** 원 기획서 §6.3에 배지 *정책*(랭킹 금지·개수 정렬 금지·양도 불가)은
있지만 MVP가 발급하는 배지는 없습니다. 지금 내놓는 것은 배지가 아니라
**결정 하나하나의 검증 가능한 기록**입니다.

## 데모의 한계

**조회 완전성을 보장하지 못합니다.** 화면의 목록은 RPC로 조회된 것이고,
"조회된 것이 전부"라는 보장이 없습니다. 그래서 모든 목록에
「조회된 것이 전부라는 보장은 없습니다」를 표시하고 **건수를 세지 않습니다.**

**소유권이 아직 배포 지갑에 있습니다.** `POIDecisionResolver`의 owner를 multisig로
옮겨야 합니다(O6). `renounce`는 하지 않습니다 — Phase 1 지표 추가가 필요합니다.

**법률 검토 게이트가 열려 있습니다.** 정산 상태·이의 공개 범위가 기획 A.6과
충돌하지 않는지 확인이 남아 있고, 정식 배포 전에 봅니다.

## 운영에 대한 정직한 서술

**아직 실사용자가 없습니다.** 지금 온체인에 있는 것은 데모 fixture입니다.
사용자 수·활성도에 대한 어떤 수치도 제시하지 않습니다.

**콜드스타트 문제가 풀리지 않았습니다.** 검증할 판단이 쌓여야 가치가 생기는데,
초기에는 쌓일 이유가 약합니다. 기획서 §7에 접근을 적었지만 검증되지 않았습니다.

## 개발 중 실제로 틀렸던 것

문서에 "이렇게 만들었다"만 적으면 무엇이 위험한지 보이지 않습니다.

- **조건 기호 6개가 전부 잘못 표시됐습니다.** `op=1`은 `≥`인데 화면엔 `≠`.
  단위 테스트 80개가 통과하는 동안 잡히지 않았고, 배포된 화면을 눈으로 보고 발견했습니다.
  검증 제품에서 조건을 잘못 보여주는 것은 가장 나쁜 종류의 결함입니다.
- **`forge script`의 UID 출력을 믿었다가 틀린 값을 기록했습니다.** EAS UID는 블록 시각을
  포함해 시뮬레이션 값과 다릅니다. 화면에 「기록을 찾을 수 없습니다」가 떠서 발견했습니다.
- **CSS `::before`가 접근성 이름에 포함돼 E2E 11개가 깨졌습니다.** 스크린리더가
  슬래시를 읽던 실제 접근성 결함이기도 했습니다.

**셋 다 테스트가 아니라 실행이 잡았습니다.**
