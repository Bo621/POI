POI 구현 루프를 실행한다. 대상: **$ARGUMENTS**

## 호출 형태 — 어디까지 갈지는 인자가 정한다

| 입력 | 범위 |
|---|---|
| `/goal C5` | **C5 하나만.** 끝나면 보고하고 멈춘다 |
| `/goal C5,C6` | 지정한 항목들을 순서대로 |
| `/goal all` · `/goal 계속` | **큐 순서대로 계속 간다.** 한 항목이 막히면 건너뛰고 다음. 아래 무인 모드 규칙 적용 |
| `/goal` (인자 없음) | 다음 P0 하나를 자동 선택해서 하나만 |
| `/loop /goal all` | 세션이 열려 있는 한 스스로 깨어나며 계속 (자는 동안용) |

연속 모드에서 턴이 끝나 멈추더라도 상태는 `BACKLOG.md`에 있다 —
다시 `/goal 계속`이라고 하면 정확히 그 지점부터 이어간다.

## 시작 절차 (이 순서 그대로)

1. `docs/GOAL.md`를 읽는다. 루프·토큰 규칙·명세 절 인덱스·이미 고정된 결정이 전부 거기 있다.
2. `docs/BACKLOG.md`에서 대상 항목의 행만 읽는다.
   - **$ARGUMENTS가 비어 있으면**: `GOAL.md`의 "남은 순서"를 보고, 선행 조건이 모두 `[x]`인
     미완료 **P0** 항목 중 가장 앞선 것을 고른다. 고른 이유를 한 줄로 말하고 시작한다.
3. 명세는 **전체를 읽지 않는다.** `GOAL.md`의 § 인덱스로 해당 줄 범위만 `sed -n 'A,Bp'`로 읽는다.

## 실행

`docs/GOAL.md`의 10단계 루프를 따른다. 요약:

```
브랜치 → 테스트 먼저 구현 → forge test / pnpm -C core test
→ 커밋 → codex review → [P1] 전건 수정 + 회귀 테스트 → GATE PASS까지 재리뷰
→ BACKLOG.md 상태 갱신 → main에 --no-ff 병합 → push
```

**게이트는 협상 대상이 아니다.** `[P1]`이 하나라도 남으면 `[x]`로 표시하지 않고 병합하지 않는다.
`[P2]`는 반영하거나, 반영하지 않는 근거를 남긴다.

## 보고

끝나면 짧게 보고한다:

- 무엇을 구현했고 어떤 불변식을 강제했는가 (명세 절·불변식 번호)
- codex가 무엇을 잡았는가 — 라운드 수, `[P1]`/`[P2]` 건수, 그중 실제 결함이었던 것
- 검증 결과 (`forge test N/N`)
- 명세와 다르게 간 것이 있으면 그 이유
- 다음 항목과 남은 백로그 개수

막히면 3회 시도 후 멈추고, 무엇을 시도했고 무엇이 막는지 말한다. 추측으로 넘어가지 않는다.

## 무인 실행 모드 (`/goal` 인자 없음 = 밤 큐)

사람이 없는 동안 돌 때는 아래가 추가로 적용된다. **판단이 필요한 일은 하지 않는다** —
기계로 검증되는 것만 한다(테스트·리뷰 게이트).

### 큐 — 이 순서로, 앞이 막히면 건너뛰고 다음

```
1  C4 → C5 → C6            리졸버 3종 (MockEAS 단위 테스트)
2  CT01~CT19               공격 테스트 — 포크에서 실제 EAS 상대로
3  C8 · C9                 ABI 대조 · 배포 스크립트 (포크 드라이런까지만)
4  X4 → X5 → X6 → X7       core TS 순수 함수
5  V1 · V2                 verifier — 포크의 정산과 대조
6  W1~W8                   프론트. **여기까지 오면 브랜치에만 두고 main 병합 금지**
                           아침에 사람이 보고 판단한다
```

### 절대 하지 않는 것

| 금지 | 이유 |
|---|---|
| 공개 테스트넷 트랜잭션·배포·파우셋 | 되돌릴 수 없다. G0(가스·법률 게이트)는 사람 몫 |
| V3 metric 정의 문서 **내용** 작성 | 데이터 출처·결측치 정책은 판단이다. 골격만 두고 남긴다 |
| `docs/POI_v0.10.md` · `docs/POI_TechSpec_v3.md` · `POI_Deploy_Guide.md` 수정 | 원본 문서다. 불일치를 찾으면 NIGHT_LOG에 적기만 |
| force-push · 히스토리 재작성 · 파일 삭제 | 복구 비용이 크다 |
| 명세에 없는 기능 추가 | `PLAN.md` §3 범위 경계 |

### 막혔을 때 — 밤을 멈추지 않는다

한 항목에서 **3회 실패**(테스트가 안 잡히거나 `[P1]`이 안 닫히면):

1. 그 항목을 `[~]`로 두고 완료 조건 칸에 막힌 지점을 한 줄로 적는다
2. `docs/NIGHT_LOG.md`에 무엇을 시도했고 무엇이 막았는지 기록
3. **다음 항목으로 넘어간다.** 하나 때문에 밤 전체를 세우지 않는다

### 기록

매 항목이 끝날 때마다 `docs/NIGHT_LOG.md`에 한 줄씩 남긴다 — 아침에 이 파일만 읽으면
밤새 무슨 일이 있었는지 복구된다.

```
| 시각 | 항목 | 결과 | codex 라운드 | 비고 |
```

큐가 비면 정지하고 요약을 남긴다.
