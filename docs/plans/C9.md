# C9 배포 스크립트 `script/Deploy.s.sol` (§6.6)

§6.6의 1~6단계를 스크립트 하나로 만든다. **7단계(addMetric)와 8단계(소유권 이전)는 넣지 않는다** —
7은 지표 정의 문서(V3)가 있어야 하고, 8은 multisig 주소가 정해져야 한다. 둘 다 사람의 판단이다.

이 항목은 **포크 드라이런까지**다. `--broadcast`를 쓰지 않는다. 실제 배포는 O3이고 O2(법률 게이트) 뒤다.

## 파일

- 새로: `contracts/script/Deploy.s.sol`
- 새로: `contracts/test/fork/Deploy.fork.t.sol` — 스크립트를 포크에서 실행해 결과를 검증
- **그 외 파일 수정 금지.** `src/`·`foundry.toml`·기존 테스트 손대지 않는다.

## `Deploy.s.sol`

`forge-std/Script.sol`의 `Script`를 상속. `contract Deploy is Script`.

### 입력 (환경변수, 기본값 있음)

```
EAS              기본 0x4200000000000000000000000000000000000021
SCHEMA_REGISTRY  기본 0x4200000000000000000000000000000000000020
```

`vm.envOr("EAS", address(0x4200...0021))` 형태로 읽는다.

### 배포 결과를 담는 구조체

스크립트를 테스트에서 호출해 결과를 검증할 수 있도록, 상태를 public 필드가 아니라
**반환 구조체**로 넘긴다.

```solidity
struct Deployment {
    address note;
    address decision;
    address settlement;
    address challenge;
    bytes32 noteSchemaUID;
    bytes32 decisionSchemaUID;
    bytes32 settlementSchemaUID;
    bytes32 challengeSchemaUID;
}
```

### 진입점 둘

```solidity
/// forge script 진입점. 브로드캐스트 구간을 연다.
function run() external returns (Deployment memory d) {
    vm.startBroadcast();
    d = _deploy();
    vm.stopBroadcast();
    _log(d);
}

/// 테스트가 브로드캐스트 없이 부르는 진입점.
function deployForTest() external returns (Deployment memory) {
    return _deploy();
}
```

### `_deploy()` — §6.6 순서 그대로

```
1. note       = new POINoteResolver(eas)
   decision   = new POIDecisionResolver(eas)
   settlement = new POISettlementResolver(eas)
   challenge  = new POIChallengeResolver(eas)

2~5. registry.register(<스키마 문자열>, ISchemaResolver(<리졸버>), <revocable>)
   poi.note.v1        revocable = false
   poi.decision.v1    revocable = false
   poi.settlement.v1  revocable = true
   poi.challenge.v1   revocable = true

6. note.initialize(noteSchemaUID)
   decision.initialize(decisionSchemaUID, noteSchemaUID)
   settlement.initialize(settlementSchemaUID, decisionSchemaUID)
   challenge.initialize(challengeSchemaUID, settlementSchemaUID)
```

각 `initialize` 직후 `require(<리졸버>.initialized(), "...")`로 확인한다.
스키마 UID가 0이 아닌 것도 등록 직후 확인한다.

### 스키마 문자열 — 오타 하나가 전부를 무너뜨린다. 그대로 복사할 것

```
poi.note.v1
bytes32 contentCommitment

poi.decision.v1
bytes32[] parents,bytes32 promotedFromNote,bytes32 verifiedAddressUID,bytes32 decisionCommitment,bytes32 triggerCommitment,bytes32 evidenceCommitment,bytes32 reasonCommitment,bool hasExpectedOutcome,bytes32 outcomeMetricId,uint8 outcomeOp,int128 outcomeThreshold,uint64 windowStart,uint64 windowEnd,uint32 graceSeconds

poi.settlement.v1
bytes32 decisionUID,uint8 result,bool hasObservedValue,int128 observedValue,string source,uint64 observedAt,string verifierVersion,bytes32 supersedes

poi.challenge.v1
bytes32 settlementUID,uint8 claimedResult,bool hasObservedValue,int128 observedValue,string source,uint64 observedAt,bytes32 noteCommitment
```

이 문자열들은 `contracts/test/fork/POIFullStack.fork.t.sol`에 이미 같은 값이 있다.
**복사해 오되, 상수를 공유하려고 그 테스트 파일을 수정하지는 말 것.**

### `_log(d)`

`console2.log`로 주소 4개와 스키마 UID 4개를 출력한다. 배포 후 사람이 기록해야 하는 값이다.
마지막에 남은 수동 단계를 출력한다:

```
남은 단계 (스크립트가 하지 않는다):
  7. addMetric x N  — V3 지표 정의 문서가 있어야 한다 (definitionHash != 0)
  8. transferOwnership -> multisig, acceptOwnership. renounce 하지 않는다 (B13)
```

## `Deploy.fork.t.sol` — 검증

`contract DeployForkTest is EASForkBase`. `setUp()`에서 `_forkSetUp()`.

`Deploy` 스크립트를 `new Deploy()`로 만들고 `deployForTest()`를 호출한다.
**브로드캐스트를 쓰지 않는다.**

| # | 테스트 이름 | 확인 |
|---|---|---|
| 1 | `test_Fork_Deploy_AllResolversReady` | 리졸버 4종 모두 `initialized() == true`, `schemaUID()`가 등록된 UID와 일치 |
| 2 | `test_Fork_Deploy_SchemaRevocabilityMatchesSpec` | `registry.getSchema(uid)`의 `revocable`이 note·decision은 false, settlement·challenge는 true |
| 3 | `test_Fork_Deploy_SchemaResolverBinding` | 각 스키마의 `resolver`가 해당 리졸버 주소 |
| 4 | `test_Fork_Deploy_CrossReferencesWired` | `decision.noteSchemaUID()==noteUID` · `settlement.decisionSchemaUID()==decisionUID` · `challenge.settlementSchemaUID()==settlementUID` |
| 5 | `test_Fork_Deploy_OwnerIsDeployer` | 리졸버 4종의 `owner()`가 스크립트를 실행한 주소(= `Deploy` 컨트랙트 자신) |
| 6 | `test_Fork_Deploy_AttestWorksAfterDeploy` | 배포 직후 노트 1건 발행이 실제 EAS를 통해 성공 |
| 7 | `test_Fork_Deploy_NoMetricsRegistered` | `decision.metrics(keccak256("BTC_30D_REALIZED_VOL_AT_END")).allowed == false` — 스크립트가 지표를 등록하지 않는다는 것을 고정 (O5는 별개 단계) |

5번 주의: `_deploy()`가 `Deploy` 컨트랙트 컨텍스트에서 실행되므로 `msg.sender`는 `Deploy`다.
실제 배포에서는 `vm.startBroadcast()`가 EOA로 바꾼다. 테스트에서는 `address(deploy)`와 비교하면 된다.

## 하지 말 것

- `--broadcast` 절대 금지. 개인키·`.env` 사용 금지.
- `addMetric`을 스크립트에 넣지 말 것 (O5, V3 선행).
- `transferOwnership`을 스크립트에 넣지 말 것 (O6, multisig 주소 미정).
- `src/` 수정 금지. 명세 문서(`docs/POI_*.md`) 읽지 말 것.
