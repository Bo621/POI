# V3 지표 정의 문서 — manifest 생성과 검증 하네스

문서 2종은 이미 작성됐다:

```
docs/metrics/BTC_PRICE_KRW_AT_END.md
docs/metrics/BTC_MAX_DRAWDOWN_IN_WINDOW.md
```

**이 문서들의 내용을 수정하지 말 것.** 해시가 `definitionHash`가 되므로 한 글자만 바뀌어도
다른 지표가 된다. 이 항목이 할 일은 해시를 뽑아 고정하고, 문서가 바뀌면 테스트가 깨지게 만드는 것이다.

## 파일

- 새로: `scripts/gen_metric_manifest.sh` — `cast keccak`로 해시 생성
- 새로: `docs/metrics/manifest.json` — 위 스크립트의 출력물 (커밋한다)
- 새로: `core/src/metrics.ts` — manifest를 읽어 쓰는 상수·타입
- 새로: `core/test/metrics.test.ts` — 검증 하네스
- 수정: `core/src/index.ts` — `export * from "./metrics.ts";` 한 줄
- **그 외 파일 수정 금지.** 특히 `docs/metrics/*.md` 두 파일은 절대 건드리지 말 것.

## `scripts/gen_metric_manifest.sh`

X1의 `scripts/gen_commitment_vectors.py`와 같은 원칙이다: **기대값을 구현이 만들지 않는다.**
Foundry의 `cast keccak`(독립 경로)로 만들고, TS는 그것을 대조만 한다.

```bash
#!/usr/bin/env bash
set -euo pipefail
# 문서 파일의 원문 바이트를 그대로 keccak256 한다.
#   definitionHash = keccak256(파일 바이트 전체)
# metricId = keccak256(utf8(지표 이름))
```

각 지표에 대해:

- `metricId`  = `cast keccak "<이름>"` (문자열 그대로. `0x` 접두 hex가 아니다)
- `definitionHash` = 파일 바이트를 hex로 만들어 `cast keccak 0x<hex>`
  (`xxd -p -c 999999 <file> | tr -d '\n'` 로 hex를 만든다)

출력 `docs/metrics/manifest.json` 형식:

```json
{
  "version": "poi.metrics.v1",
  "generatedBy": "scripts/gen_metric_manifest.sh (cast keccak)",
  "metrics": [
    {
      "name": "BTC_PRICE_KRW_AT_END",
      "metricId": "0x…",
      "doc": "docs/metrics/BTC_PRICE_KRW_AT_END.md",
      "definitionHash": "0x…",
      "decimals": 0,
      "kind": 0,
      "unit": "krw"
    },
    {
      "name": "BTC_MAX_DRAWDOWN_IN_WINDOW",
      "metricId": "0x…",
      "doc": "docs/metrics/BTC_MAX_DRAWDOWN_IN_WINDOW.md",
      "definitionHash": "0x…",
      "decimals": 1,
      "kind": 0,
      "unit": "percent"
    }
  ]
}
```

`decimals`·`kind`·`unit`은 **문서에 적힌 값 그대로** 쓴다. 스크립트에 하드코딩해도 되지만,
값을 임의로 정하지 말고 문서의 표를 보고 옮길 것. `kind`는 둘 다 `0`
(`WINDOW_END_EVALUATED` — 컨트랙트가 `kind != 0`을 거부한다).

JSON은 2칸 들여쓰기, 마지막 줄바꿈 하나.

## `core/src/metrics.ts`

```ts
export interface MetricDefinition {
    name: string;
    metricId: Hex;
    doc: string;
    definitionHash: Hex;
    decimals: number;
    kind: number;
    unit: string;
}

/** docs/metrics/manifest.json 의 내용. 빌드 시 JSON을 import 하지 말고 상수로 둔다 */
export const METRICS: readonly MetricDefinition[];

export function metricByName(name: string): MetricDefinition | undefined;
export function metricById(metricId: Hex): MetricDefinition | undefined;
```

**JSON을 import 하지 않는 이유**: `core`는 브라우저 번들에도 들어간다. 파일시스템 접근
없이 값을 쓸 수 있어야 한다. manifest의 값을 이 파일에 **복사해 상수로 박는다.**
아래 테스트가 manifest와의 일치를 강제하므로 손으로 복사해도 어긋나면 바로 깨진다.

## `core/test/metrics.test.ts` — 하네스가 이 항목의 핵심

| # | 내용 |
|---|---|
| 1 | `docs/metrics/manifest.json`을 읽어 `METRICS` 상수와 **완전히 일치**하는지 (필드 하나라도 다르면 실패) |
| 2 | **문서 파일을 직접 읽어 `keccak256(바이트)`를 재계산**해 manifest의 `definitionHash`와 대조. viem의 `keccak256`을 쓴다 — `cast`와 독립 경로다. **문서를 고치고 manifest를 다시 만들지 않으면 여기서 깨진다** |
| 3 | `metricId === keccak256(utf8(name))` 재계산 대조 |
| 4 | 모든 `definitionHash`가 0이 아니다 (컨트랙트가 0을 거부한다) |
| 5 | 모든 `kind === 0` (컨트랙트가 `kind != 0`을 거부한다) |
| 6 | `metricId`가 서로 다르다 (충돌 없음) |
| 7 | `doc` 경로의 파일이 실제로 존재한다 |
| 8 | `metricByName` / `metricById` 조회가 동작하고, 없는 값에 `undefined` |

경로는 `new URL("../../docs/metrics/", import.meta.url)` 기준으로 잡는다
(`core/test/errors.test.ts`가 `contracts/src`를 읽는 방식과 같다).

## 하지 말 것

- `docs/metrics/*.md` 두 파일을 **수정하지 말 것.** 오타를 발견해도 고치지 말고 보고할 것 —
  해시가 바뀌면 다른 지표가 된다.
- 지표를 더 추가하지 말 것. 이번 범위는 2종이다.
- 관측값을 실제로 가져오는 구현(`MetricProvider`)을 넣지 말 것. 그건 별도 항목이다.
- `verifier/`·`contracts/`·`web/` 수정 금지.
- 명세 문서(`docs/POI_TechSpec_v3.md` 등) 읽지 말 것.

## 검증

```
bash scripts/gen_metric_manifest.sh      # manifest.json 생성 (재실행해도 같은 값)
cd core && npm test                      # 54 + 8 = 62/62
cd core && npx tsc --noEmit
```
