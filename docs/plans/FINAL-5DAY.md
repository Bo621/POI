# ① 온체인 실행 정합성 — 8/4~8/5

## 설계 — 스키마를 바꾸지 않습니다

`DecisionData` 에 지갑 필드가 없습니다. 스키마를 바꾸면 배포된 컨트랙트·스키마 UID·
공개 URL·기존 기록 6건이 **전부 깨집니다.** 바꾸지 않습니다.

**대신 지표를 하나 등록합니다.**

```
지표   HL_PERP_OPEN_LONG_QTY
정의   결정 payload 에 선언된 지갑·종목에 대해,
       관측 구간 내 Open Long 체결 수량의 합
출처   온체인 파생거래소 공개 API — 인증 없음 (실측 완료)

결정   metricId = 위 지표 · op = GT · threshold = 0
       뜻: 「이 구간에 이 지갑에서 롱을 연다」
정산   실제 체결에서 관측값 산출 → 컨트랙트가 재계산해 대조
```

지갑·종목은 **payload 에 선언되고 공개 시 드러납니다.** 지금 「이유」를 다루는
방식과 같습니다. 관측값의 진실성은 컨트랙트가 보장하지 않고, **제3자가 같은
공개 API 로 재현하고 어긋나면 이의를 남깁니다** — 기존 설계 그대로입니다.

> **25쪽 확장 슬라이드가 이미 이렇게 주장합니다** — 「컨트랙트는 고정된 내용이
> 무엇인지 보지 않는다. 고정할 내용만 바꾸면 다른 것도 같은 방식으로 증명된다.」
> **이 작업이 그 주장을 그 자리에서 증명합니다.**
