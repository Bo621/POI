# C5-R2 정산 payload 정규성 테스트 보강

C6 리뷰에서 발견된 것과 **같은 결함**이 C5에 있다. 변이 테스트로 확인됨:
`POISettlementResolver._requireCanonicalPayload`의 `keccak256` 대조를 **길이 대조**로
약화시켜도 기존 테스트가 전부 통과한다. 즉 "잉여 바이트"만 잡히고 **비정규 인코딩**은 안 잡힌다.

## 파일

- 수정: `contracts/test/POISettlementResolver.t.sol` — **테스트 하나만 추가**
- 그 외 전부 수정 금지. 특히 `contracts/src/` 는 손대지 말 것.

## 추가할 테스트

```
test_Attest_RevertsOnDirtyStringPadding
```

이미 있는 `test_Attest_RevertsOnDirtyStringPadding`이 C6 테스트 파일
(`contracts/test/POIChallengeResolver.t.sol`)에 있다. **그것과 같은 방식**으로 쓴다.

- `_settlementData(_settlement())`로 정규 인코딩을 만든다.
- 정산 스키마에는 문자열이 둘이다: `source = "upbit"`(5바이트),
  `verifierVersion = "poi-verifier/1.0.0"`(18바이트). 둘 다 마지막 워드에 패딩이 남는다.
- 인코딩의 **마지막 바이트를 0xFF로 바꾼다** (`verifierVersion` 본문의 패딩 영역).
  길이는 변하지 않는다.
- `vm.expectRevert(POISettlementResolver.MalformedPayload.selector)` 후 `_attest`.

## 검증

`cd contracts && forge test` → **144/144**.

그리고 변이 확인: `_requireCanonicalPayload`의
`if (keccak256(data) != keccak256(canonical))` 를
`if (data.length != canonical.length)` 로 바꾸면 **이 새 테스트만 실패해야 한다.**
확인 후 반드시 원복할 것 — `src/`에 변경이 남으면 안 된다.
