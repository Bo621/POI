## 1. `[P1]` 고정 네비게이션이 페이지 제목을 가린다

`#/record`에서 `기록하기` 제목이 nav 아래로 잘려 보인다.

```css
main { padding-block-start: calc(var(--nav-height) + var(--space-9)); }
html { scroll-padding-block-start: var(--nav-height); }
```

`--nav-height`를 토큰으로 두고 nav도 그 값을 쓴다. **모든 라우트에서 확인할 것.**

## 2. `[P1]` 제목 아래 빈 공간이 크다

문서 머리(제목 + 괘선)와 첫 절 사이가 비어 있어 화면이 비어 보인다.
원인은 `.doc-section`의 `margin-top: --space-9`가 **첫 절에도** 붙기 때문이다.

```css
.doc-section:first-of-type { margin-block-start: var(--space-6); }
```

절 사이 간격도 한 단계 줄인다: `--space-9` → `--space-6`.
**리듬을 없애라는 것이 아니다** — 묶음 안(`--space-4`)과 묶음 사이(`--space-6`)의
차이는 유지한다.

## 3. `[P2]` `GIWA Sepolia · chainId 91342`가 모든 화면에 반복된다

nav에 체인 정보를 이미 넣을 수 있다. **홈에만 남기고** 다른 화면의 문서 머리에서는 뺀다.
nav 오른쪽(지갑 옆)에 `· 91342` 정도로 짧게 두면 충분하다.

## 4. `[P1]` 홈의 예시 증서가 목록이 아니다

지금은 항목마다 `상태/UID/보기` 3행 정의목록이라 4건이 한 화면을 채운다.
와이어프레임(SITEMAP §R1-8)은 **한 줄**이다.

```
▣ 정산완료      0xf6f0…af5e                              [보기 →]
▣ 정산완료      0xe664…80a1   정산 철회 이력 있음          [보기 →]
▣ 기한초과      0x755e…edff                              [보기 →]
▣ 대기          0x6180…b37b                              [보기 →]
```

- **인장을 작게 표시한다.** `.seal--sm`(지름 2.5rem, 글자 `--text-xs`)을 추가한다.
  기존 `.seal`의 변형이지 새 스타일이 아니다.
- 한 줄 배치는 `display:grid; grid-template-columns: auto 1fr auto auto`.
- 좁은 화면에서는 두 줄로 접힌다.
- **개수를 세지 않는다.**

같은 한 줄 형식을 `#/me`·`#/passport`의 목록에도 쓴다. **세 곳이 같은 컴포넌트를 쓴다** —
`web/src/recordRow.tsx`로 뽑는다.

## 5. `[P1]` 상태 문구가 두 벌이다

목록에는 `정산됨`·`정산 기한 초과`·`구간 시작 전`이 나오는데
인장은 `정산완료`·`기한초과`·`대기`다. **같은 상태를 다르게 부른다.**

인장 문구(2~4글자)를 정본으로 삼고, 긴 설명이 필요한 자리에서만 풀어 쓴다.

| 상태 | 인장(정본) | 풀어 쓸 때 |
|---|---|---|
| NOT_REQUIRED | 해당없음 | 예상 결과를 선언하지 않음 |
| PENDING | 대기 | 관측 구간 시작 전 |
| OBSERVING | 관측중 | 관측 구간 진행 중 |
| AWAITING | 정산대기 | 구간이 끝나 정산할 수 있음 |
| OVERDUE | 기한초과 | 유예까지 지나 정산 기한이 지남 |
| SETTLED | 정산완료 | 정산됨 |
| SETTLED_LATE | 지연정산 | 기한 후에 정산됨 |

**한 곳(`core` 또는 `web/src/stateLabel.ts`)에서 정의**하고 전부 그것을 쓴다.
`core`는 표시 문구를 갖지 않는 편이 맞으므로 `web/src/stateLabel.ts`에 둔다.

## 6. `[P2]` `#/verify`의 ② 공개 대조가 절로서 무겁다

안내 한 줄뿐인데 `<h2>`를 차지한다. **①의 보조 문구로 내린다.**
결과적으로 `기록 열기` / `오프체인 verifier` 두 절이 된다.

## 7. `[P2]` `#/record`의 3단계 표시가 진행을 나타내지 않는다

①②③이 나란히 있을 뿐 현재 단계를 강조하지 않는다.
**현재 작업 중인 단계를 인주색으로 강조**하고 나머지는 `--ink-faint`.

단계는 사용자의 진행에 따라 바뀐다:

```
저널만 있음        → ① 강조
노트를 발행함      → ② 강조
결정 폼을 채우는 중 → ③ 강조
```

상태를 새로 만들지 말고 **이미 있는 값**(저널 개수·노트 영수증·결정 폼 입력 여부)으로 판단한다.

## 8. `[P2]` 경고가 연속으로 두 개 붙는다

`#/record` 상단에 `지갑 연결 안내`(회색)와 `이 기록은 검증되지 않습니다`(인주)가
연달아 나온다. 지갑 안내는 **nav에 이미 상태가 있으므로** 절 안으로 옮기거나
`.doc-note`로 낮춘다. **인주색 경고는 화면당 하나가 원칙**이다.

## 리뷰 대응 R1 — 손질로 바뀐 표시를 테스트가 따라가지 못한다

19/26. 실패 4건 전부 **의도한 표시 변경** 때문이다. 제품을 되돌리지 않는다.

### 1. 목록의 UID가 축약됐다

`recordRow`가 한 줄 형식이 되면서 UID를 `0x95d7…bc2f`로 줄여 보여준다.
테스트가 **전체 UID 문자열**을 exact로 찾는다.

**고칠 것**: 목록에서는 축약형으로 찾거나, 행에 `title`/`data-uid` 없이도
찾을 수 있게 **축약 정규식**을 쓴다. 예: `new RegExp(uid.slice(0,6) + ".*" + uid.slice(-4), "i")`.

전체 UID가 필요한 단언은 **상세 화면**에서 한다(거기서는 전체가 보인다).

### 2. `대기`가 두 번 나온다

상태 문구를 한 곳으로 통일하면서 **인장(`role="img"` aria-label)과 텍스트 라벨**이
같은 문구를 갖는다. `getByText("대기", {exact:true})`가 2개를 잡는다.

**고칠 것**: 인장은 `getByRole("img", {name: "상태: 대기"})`로,
텍스트 라벨은 그 절 안으로 범위를 좁혀 찾는다. **둘 다 있는 것이 정상**이다
(색만으로 구별하지 않기 위해 인장에 글자를 넣기로 했다 — W-DESIGN §9).

### 3. `지갑 없이…`·`Passport` 실패도 같은 원인

같은 기준으로 훑는다. `web/e2e` 전체에서 **목록 항목을 exact 전체 UID로 찾는 자리**를 전수 확인.

### 하지 말 것

- 축약을 되돌리지 말 것. 한 줄 목록은 SITEMAP §R1-8이 요구한 것이다.
- 상태 문구를 두 벌로 되돌리지 말 것.
- 단언을 약화하지 말 것 — **어디서 어떻게 찾는지만** 바꾼다.

### 검증

```
bash scripts/dev_up.sh && cd web && npm run test:e2e     # 26/26, skipped 0
```

## 리뷰 대응 R2 — 같은 문제가 상세 화면 테스트에 남았다

23/26. R1을 목록에만 적용하고 **상세 화면 테스트에는 적용하지 않았다.**

```
getByText('정산완료', {exact:true}) resolved to 2 elements:
  1) <div role="img" aria-label="상태: 정산 완료" class="seal …">정산완료</div>
  2) (텍스트 라벨)
```

### 1. `read.spec.ts`의 상세 상태 단언

인장은 `getByRole("img", {name: …})`로, 텍스트 라벨은 그 절 안으로 좁혀 찾는다.
**`web/e2e` 전체에서 `getByText("<상태문구>", {exact:true})`를 쓰는 자리를 전수 확인할 것.**
R1에서 일부만 고쳐 같은 실패가 반복됐다.

### 2. `[P2]` 인장의 `aria-label`과 표시 문구가 다르다

```
aria-label="상태: 정산 완료"   (띄어쓰기 있음)
표시 텍스트  "정산완료"          (없음)
```

W-POLISH §5에서 상태 문구를 한 곳으로 통일했는데 **`aria-label`이 그 통일에서 빠졌다.**
스크린리더 사용자와 화면이 다른 말을 듣는다.

`stateLabel.ts`의 정본 문구를 `aria-label`에도 쓴다: `상태: 정산완료`.
**모든 상태에 대해 확인할 것**(`기한 초과`→`기한초과`, `정산 대기`→`정산대기` 등).

E2E의 `getByRole("img", {name: "상태: …"})` 단언도 함께 맞춘다.

## 리뷰 대응 R3 — `[P1]` 홈의 예시 증서가 사라졌고, 왜인지 알 수 없다

화면에 `예시 증서` 절이 **아예 없다**(`h2`가 `기록 열기` 하나뿐).
시드는 새로 만들었고 페이지에서 RPC도 정상이다(`eth_chainId` → `0x164ce`).

`home.tsx:83`

```ts
void loadSummaries(exampleUIDs).then(setExamples).catch(() => setExamples([]));
…
{examples.length > 0 && <section …><h2>예시 증서</h2>…</section>}
```

**실패를 조용히 삼키고 절을 통째로 숨긴다.** 그래서 화면에도 콘솔에도 아무 단서가 없다.

지갑 없는 심사자가 들어올 유일한 입구가 예시 증서다. **말없이 사라지면 안 된다.**

### 고칠 것 1 — 실패를 드러낸다 (제품)

`예시 증서`·`최근 열어본 증서`·`처리할 기록` 모두:

| 상태 | 화면 |
|---|---|
| 불러오는 중 | `"불러오는 중…"` |
| 성공, 항목 있음 | 목록 |
| 성공, 항목 없음 | `"표시할 기록이 없습니다."` (`.doc-note`) |
| **실패** | **`! 예시 증서를 불러오지 못했습니다.` + 오류 메시지 + `[다시 시도]`** |

`catch(() => setState([]))`처럼 **오류를 버리는 패턴을 홈 전체에서 없앤다.**
`web/src` 다른 화면에도 같은 패턴이 있는지 훑을 것.

### 고칠 것 2 — 그래서 왜 실패하는가

1번을 고치면 화면에 사유가 뜬다. 그것을 보고 고친다.

유력한 후보(추측이며 사유를 보고 판단할 것):

- `seed.json`을 `import`로 번들에 넣는데 **dev 서버가 옛 내용을 물고 있다**
  (시드를 다시 만들면 UID가 바뀐다). 그렇다면 `import` 대신 **런타임 `fetch`**로 읽어야 한다 —
  시드를 다시 만들 때마다 dev 서버를 재시작해야 하는 것은 결함이다.
- `loadSummaries`가 한 건이라도 실패하면 전체가 reject된다.
  **한 건 실패가 나머지를 가리면 안 된다** — `Promise.allSettled`로 바꾸고
  실패한 항목만 `"불러오지 못함"`으로 표시한다.
