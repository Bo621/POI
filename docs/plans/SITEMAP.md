# SITEMAP 화면 기획 — 사이트맵과 와이어프레임

## 0. 지금 구조의 문제

한 페이지에 9개 절이 순서 없이 나열돼 있다.

```
지갑 · 저널과 노트 · 결정 커밋 · 정산 · 이의 · 상태 · 결정 DAG · Strategy Passport · 공개
```

**기능은 다 있는데 "누가 무엇을 하러 왔는지"가 없다.** 구체적으로:

| | |
|---|---|
| 1 | 세 종류의 사람(기록자·검증자·이의 제기자)이 한 화면에 섞여 있다 |
| 2 | **하나의 결정을 다루는 정보가 다섯 절에 흩어져** UID를 계속 복사해 붙여야 한다 |
| 3 | 시간이 흐르는 물건인데 **"지금 내가 할 일"이 없다** — 정산할 때가 된 결정을 알 수 없다 |
| 4 | POI가 무엇을 증명하는지 화면에 없다 |
| 5 | 딥링크가 없어 심사자에게 "이 결정을 보라"고 줄 URL이 없다 |

---

## 1. 사용자와 그가 하려는 일

| | 누구 | 하려는 일 | 지갑 |
|---|---|---|---|
| **A** | 기록자 | 판단을 남기고, 때가 되면 정산한다 | 필요 |
| **V** | 검증자 (제3자·심사자) | 남의 기록을 조회하고 대조한다 | **불필요** |
| **B** | 이의 제기자 | 남의 정산에 이의를 단다 | 필요 |

**V가 지갑 없이 전부 할 수 있어야 한다.** 그것이 B10("서버를 신뢰하지 않는다")의 요점이고,
심사자가 가장 먼저 시도할 경로다.

## 2. 시간 축 — 이 제품의 뼈대

```
t0        커밋        결정이 존재했다는 사실이 고정된다
          ↓
windowStart ~ windowEnd   관측 구간 (아무것도 할 수 없다. 기다린다)
          ↓
windowEnd            정산 가능
          ↓
+ graceSeconds       이 선을 넘으면 OVERDUE — 되돌릴 수 없다
```

**화면은 이 축을 따라야 한다.** 지금은 축이 없어서 사용자가 자기가 어디에 있는지 모른다.

## 3. 사이트맵

해시 라우팅(`#/...`)을 쓴다. 정적 배포에서 서버 설정 없이 딥링크와 뒤로가기가 동작한다.
라우터 라이브러리를 도입하지 않는다 — 경로 6개에 50줄이면 충분하다.

```
#/                        홈
                          POI가 무엇을 증명하는지 3줄 + 지금 할 수 있는 일 3갈래
                          지갑 없이 볼 수 있다

#/record                  기록하기                                   [A · 지갑 필요]
                          저널 → 노트 승격 → 결정 커밋 (3단계 진행)

#/me                      내 기록                                    [A · 지갑 필요]
                          내 결정 목록 · 상태별 정렬 · "지금 할 일"

#/d/<decisionUID>         결정 상세                                  [V · 지갑 불필요]
                          ★ 이 앱의 중심. 하나의 결정에 대한 모든 것
                          상태 인장 · 등급 · 평문 필드 · 정산 · 이의 · 공개 · 계보

#/verify                  검증하기                                   [V · 지갑 불필요]
                          UID로 조회 · reveal 대조 · verifier CLI 명령

#/passport/<address>      Strategy Passport                          [V · 지갑 불필요]
                          한 지갑의 기록 나열 (순위 아님)

#/fixtures                데모 데이터                                [개발·시연]
                          seed.json이 있을 때만 메뉴에 나타난다
```

**핵심 변경: `#/d/<uid>`가 중심이 된다.** 지금 상태·DAG·정산·이의·공개로 흩어진 것이
하나의 결정 아래 모인다. UID를 다섯 번 붙여넣을 일이 없어진다.

### 네비게이션

상단 고정. 지갑이 없으면 `기록하기`·`내 기록`은 흐리게(비활성) 두되 **숨기지 않는다** —
무엇이 있는지는 보여주고, 왜 못 쓰는지 알려준다.

```
POI 판단 증서 │ 홈  기록하기  내 기록  검증하기 │ 0xf39F…2266 미검증  [연결]
```

## 4. 와이어프레임

기호: `───` 괘선 · `▣` 인장 · `[버튼]` · `▸` 접힘 · `!` 인주색 경고 · `·` 회색 보조

### 4.1 `#/` 홈

지갑 없이 열리는 첫 화면. **무엇을 증명하는 물건인지**가 먼저다.

```
════════════════════════════════════════════════════════
 POI 판단 증서
 GIWA Sepolia · chainId 91342                     [지갑 연결]
════════════════════════════════════════════════════════

 투자 판단을 내린 시점과 내용을 온체인에 고정하고,
 결과가 나온 뒤 그 판단이 맞았는지 누구나 검증할 수 있게 합니다.
 판단의 결과는 발행자가 아니라 컨트랙트가 산술로 판정합니다.

 ───────────────────────────────────────────────────────
 지금 할 수 있는 일

   판단을 남긴다              남의 기록을 검증한다        이의를 제기한다
   결정을 커밋하고 시점을      UID만 있으면 지갑 없이      정산의 관측값이
   고정합니다                  대조할 수 있습니다          틀렸다고 기록합니다
   [기록하기 →]               [검증하기 →]                · 결정 상세에서

 ───────────────────────────────────────────────────────
 ! 이 앱은 GIWA Sepolia 테스트넷에서 동작합니다. 실제 자산과 무관합니다.

 · 데모 데이터 보기 (seed.json이 있을 때만)
```

세 갈래가 §1의 세 사용자와 1:1이다. **가운데 정렬하지 않고 좌측 정렬**(W-DESIGN).

### 4.2 `#/record` 기록하기 — 3단계

3계층(저널→노트→결정)이 **왜 세 개인지**가 화면에서 보여야 한다.

```
 기록하기
 ───────────────────────────────────────────────────────
  ① 저널        ② 노트         ③ 결정
  검증 안 됨     시점 고정      시점 + 예상 결과 고정
  ●────────────○─────────────○
 ───────────────────────────────────────────────────────

 ① 저널 — 생각을 적어 둡니다
 ! 이 기록은 검증되지 않습니다  (브라우저에만 저장됩니다)

   내용  ┌──────────────────────────────┐
         └──────────────────────────────┘
   [저장]

   · 저장된 저널
     2026-07-28 09:12  "BTC 조정 국면…"      [노트로 승격 →]

 ───────────────────────────────────────────────────────
 ② 노트 — 이 내용이 이 시각에 존재했다는 것만 고정합니다
   (저널에서 승격하거나 바로 작성)
   [노트 발행]  → 발행 후 영수증(UID · 트랜잭션)

 ───────────────────────────────────────────────────────
 ③ 결정 — 예상 결과까지 선언합니다
 · trigger는 온체인에서 강제되지 않습니다
 ! 아래 항목은 평문으로 온체인에 기록됩니다
     predicate · 관측 조건 · 참조

   결정 내용 / trigger / 근거(선택) / 이유(선택)
   ▸ 예상 결과 선언                       ← 접힘. 열면 지표·op·임계·구간
   ▸ 계보 (부모 결정 · 승격 노트)          ← 접힘

   [salt 생성 및 백업]  → 모달 → 백업 확인해야 [발행] 활성
```

- **접힘(`▸`)을 쓴다.** 지금은 15개 필드가 전부 펼쳐져 있어 압도적이다.
  선택 항목은 접고, 필수만 먼저 보인다(progressive disclosure).
- 발행에 성공하면 **`#/d/<uid>`로 이동**한다. 지금은 UID만 남고 끝난다.

### 4.3 `#/me` 내 기록 — "지금 할 일"

```
 내 기록                                   0xf39F…2266
 ───────────────────────────────────────────────────────
 지금 할 일 (2)

  ▣ 정산대기   BTC 30일 변동성 판단        구간 종료 2시간 전 지남
               0x9eff…7828                        [정산하기 →]

  ▣ 기한초과   ETH 낙폭 판단               유예 3시간 지남
               0x755e…edff                        [보기 →]
 ───────────────────────────────────────────────────────
 전체 (5)

  ▣ 정산완료   …                    정산 철회 이력 있음   [보기 →]
  ▣ 대기       …                    구간 시작까지 2시간   [보기 →]
  …
 ───────────────────────────────────────────────────────
 · 조회된 것이 전부라는 보장은 없습니다.
```

- **"지금 할 일"이 맨 위.** `정산대기`·`기한초과`만 올라온다. 이것이 §2 시간 축의 UI다.
- 정렬은 **커밋 시각 내림차순 하나**. 정렬 컨트롤 없음. 점수·순위 없음.
- `기한초과`는 인주색. 되돌릴 수 없다는 것이 보여야 한다.

### 4.4 `#/d/<uid>` 결정 상세 — 이 앱의 중심

**지갑 없이 전부 읽힌다.** 쓰기 동작만 지갑을 요구한다.

```
 ← 내 기록                                      0x9eff…7828  [복사]
 ═══════════════════════════════════════════════════════
                    ┌─────────┐
                    │ 정산완료 │ ▣        상태  정산됨
                    └─────────┘           등급  SELF_DECLARED · SEALED
                                          · 왼쪽은 근거 첨부, 오른쪽은 공개 여부
                    ! 정산 철회 이력 있음
 ═══════════════════════════════════════════════════════
 커밋
   발행자      0xf39F…2266   미검증 지갑
   커밋 시각    2026-07-28 06:33:00 UTC
   검증 스냅샷  0x00…0   · 스냅샷 UID를 찾지 못했습니다
   트랜잭션    0x1234…      (로컬 체인이라 링크 없음)

 예상 결과                                    ← 평문. 온체인에 그대로 있다
   지표        BTC_PRICE_KRW_AT_END
   조건        ≥ 91,201,000
   관측 구간    07-28 06:33 ~ 06:43 UTC
   유예        1시간          → 기한 07-28 07:43 UTC

 ───────────────────────────────────────────────────────
 정산                                          [정산하기]  ← 소유자에게만
   결과        OBSERVED
   관측값       92,201,000    출처 upbit:KRW-BTC:1m
   관측 시각    구간 종료 시각(고정)
   발행        0x5d9a…09c3    트랜잭션 0x…
   · 결과는 관측값으로부터 컨트랙트가 판정합니다. 직접 고를 수 없습니다.

   ▸ 이전 정산 1건 (철회됨)                    ← 접힘. 정정 이력

 ───────────────────────────────────────────────────────
 이의                                          [이의 제기]
 · 조회된 것이 전부라는 보장은 없습니다.
   0xabc…  0x7099…79C8  미검증 지갑  NOT_OBSERVED  출처 other-exchange
   (건수 표시 없음 · 정렬 없음)

 ───────────────────────────────────────────────────────
 공개 (Reveal)
   salt와 payload를 넣으면 이 화면에서 대조합니다. 지갑이 필요 없습니다.
   attester와 commitment는 체인에서 읽습니다 — 손으로 넣을 수 없습니다.
   [대조하기]

 ───────────────────────────────────────────────────────
 계보                                          ▸ 부모 3개 (접힘)

 ───────────────────────────────────────────────────────
 오프체인 검증
   $ poi-verify 0x9eff…7828 --rpc <url> --json      [복사]
   · 이 명령이 업비트에서 값을 다시 가져와 온체인 정산과 대조합니다.
```

**이 화면 하나가 심사자에게 줄 URL이다.** 상태·근거·정산·이의·공개·계보·검증 명령이
한 곳에 있고, 지갑 없이 열린다.

### 4.5 `#/verify` 검증하기 — 지갑 없이

```
 검증하기                          지갑이 필요 없습니다
 ───────────────────────────────────────────────────────
 ① 기록 열기
   decisionUID  [0x…            ]  [열기]

 ② 공개 대조 (salt와 payload를 받았다면)
   → 결정 상세의 "공개"에서 합니다. UID를 넣으면 이동합니다.

 ③ 오프체인 verifier
   $ poi-verify <decisionUID> --rpc <url> --json
   종료코드  0 일치 · 1 불일치 · 2 조회 실패 · 3 검증 못 함
   · verifier는 업비트에서 값을 다시 가져와 온체인 정산과 대조합니다.
     지표 정의는 docs/metrics/ 에 있고 그 문서 해시가 온체인 definitionHash입니다.
```

### 4.7 `#/fixtures` 데모 데이터

`seed.json`이 있을 때만 네비게이션에 나타난다. **데모에서 UID를 복사할 필요가 없어진다.**

## 5. 프로세스별 확인

| 흐름 | 경로 | 막히는 곳이 없는가 |
|---|---|---|
| 판단 남기기 (A) | `#/` → `#/record` → 발행 → `#/d/<uid>` | salt 백업 관문이 ③에 있다. 발행 후 상세로 이동해 결과가 보인다 |
| 정산 (A) | `#/me` "지금 할 일" → `#/d/<uid>` → 정산 | 정산할 때가 된 것이 목록 맨 위에 온다 |
| 검증 (V, 지갑 없음) | `#/` → `#/verify` → `#/d/<uid>` | 전 구간 지갑 불필요. reveal도 상세에서 |
| 이의 (B) | `#/d/<uid>` → 이의 제기 | 대상 정산이 눈앞에 있다 |
| 심사자 | URL 하나(`#/d/<uid>`) | 상태·근거·정산·이의·검증 명령이 한 화면에 |
| 데모 | `#/fixtures` → 각 상태 | UID 복사가 필요 없다 |

## 6. 구현 범위와 원칙

- **디자인 톤은 그대로.** `W-DESIGN.md`의 괘선·인장·미색·인주를 재사용한다. 새 색 금지.
- **로직을 다시 쓰지 않는다.** 기존 컴포넌트를 라우트 아래로 옮겨 재배치하는 것이 대부분이다.
  순수 함수와 그 테스트(63개)는 그대로여야 한다.
- **라우터 라이브러리를 도입하지 않는다.** `web/src/router.tsx`에 해시 라우팅 50줄.
  `hashchange` 리스너 + 경로 파싱. 뒤로가기·딥링크가 동작해야 한다.
- **접힘(`▸`)은 `<details>`로.** JS 없이 접근성이 따라온다.
- 명세의 상시 표시 문구는 §4의 위치에 그대로 둔다. 하나도 빠뜨리지 않는다.
- 건수 표시·정렬·순위 금지 규칙은 그대로.

## 7. E2E에 미치는 영향

기존 16개는 **한 페이지 전제**로 쓰여 있다. 라우팅이 들어가면 선택자가 깨진다.

- E2E를 라우트 기준으로 고친다. **테스트를 지우지 말 것.**
- `fullpath.spec.ts`는 오히려 자연스러워진다 — 실제 사용자 동선과 같아진다.
- 완료 조건은 여전히 **16/16**이다.

# 개정 R1 — codex 리뷰 반영 + 홈 대시보드

codex 리뷰(2026-07-28). 구조 방향(`#/d/<uid>` 중심)은 타당하다는 확인을 받았고,
그 위에서 **실제 결함 여러 건**이 나왔다. 전부 반영한다.

## R1-1 `[P1]` 숫자 요약을 지운다 — 내 실수

와이어프레임 §4.3에 `지금 할 일 (2)` · `전체 (5)`라고 썼다.
**이것이 KPI로 읽힌다.** W10에서 "화면에 숫자 요약을 두지 않는다"를 규칙으로 정해 놓고
사이트맵에서 스스로 어겼다.

```
지금 할 일          ← 괄호 숫자 없음
전체
```

같은 이유로 `▸ 이전 정산 1건 (철회됨)` → `▸ 이전 정산 (철회됨)`,
`▸ 부모 3개` → `▸ 계보`로 고친다. **개수를 세어 보여주지 않는다.**

## R1-2 `[P1]` 이의는 정산에 붙는다, 결정이 아니라

스키마상 `poi.challenge.v1`의 `refUID`는 **`settlementUID`**다.
그런데 §4.4 와이어프레임은 이의를 결정 아래 평평하게 뒀다.
**정정이 있으면(S1 철회 → S2) 어느 정산에 대한 이의인지 구분되지 않는다.**

정산 절 안에 **정산별로 종속**시킨다.

```
 정산
   현재 (활성)      0x5d9a…09c3
     결과 OBSERVED · 관측값 92,201,000 · 출처 upbit:KRW-BTC:1m
     이의
     · 조회된 것이 전부라는 보장은 없습니다.
       0xabc…  0x7099…79C8  미검증 지갑  NOT_OBSERVED  출처 other-exchange
     [이의 제기]                      ← 이 정산에 대해

   ▸ 이전 정산 (철회됨)               ← 접힘
       0x1111…  결과 NOT_OBSERVED · 철회됨
       이의  (그 정산에 달렸던 것)
```

이의 제기 버튼도 **정산 옆에** 둔다. 무엇에 대한 이의인지가 위치로 드러난다.

## R1-3 `[P1]` 부분 실패가 상세 전체를 무너뜨리면 안 된다

결정 본문과 활성 정산은 **직접 조회**(빠르고 실패 확률이 낮다).
이의 목록과 계보는 **로그 스캔**(느리고 실패할 수 있다).

지금 설계대로면 로그 조회 하나가 실패했을 때 상세 전체가 사라진다.
**핵심 검증 URL이 부가 조회 때문에 무너진다.**

절별로 독립 로드하고 독립 실패 경계를 둔다.

```
 이의
 ! 이의 목록을 불러오지 못했습니다.  [다시 시도]
   (결정·정산은 그대로 보인다)
```

## R1-4 `[P1]` 상세 URL 복사

이 기획의 핵심 산출물은 **"심사자에게 줄 URL 하나"**인데
와이어프레임에는 UID 복사 버튼만 있었다.

```
 ← 홈                          0x9eff…7828  [UID 복사]  [이 화면 링크 복사]
```

`← 내 기록`도 제3자 진입에는 틀린 안내다 → **`← 홈`** 고정.

## R1-5 `[P1]` 오류·경계 상태를 명시한다

지금까지 "정상 경로"만 그렸다. 심사자는 반드시 깨뜨려 본다.

| 상황 | 화면 |
|---|---|
| UID 형식이 틀림 | `"UID는 0x로 시작하는 66자여야 합니다."` |
| attestation이 없음 | `"해당 기록을 찾을 수 없습니다."` + 입력 유지 |
| 다른 스키마의 UID | `"결정 기록이 아닙니다."` (노트·정산·이의 중 무엇인지 알려준다) |
| 철회된 결정 | 상단에 `! 철회된 결정입니다` |
| 컨트랙트 미배포 | 홈 상단 `! 컨트랙트가 아직 배포되지 않았습니다` · 쓰기 전부 비활성 |
| 지갑이 다른 네트워크 | `"chainId 91342로 전환해 주세요."` 자동 전환 요청 없음 |
| RPC 3회 실패 | 해당 절만 `"확인 불가"` + 재시도 |
| 알 수 없는 라우트 | `"없는 화면입니다."` + 홈 링크 |

## R1-6 `[P1]` 검증 신뢰사슬을 상세에 노출한다

심사자가 "이 값을 왜 믿나"를 물었을 때 화면에서 답이 나와야 한다.
결정 상세 하단 `▸ 검증 근거`(접힘)에:

```
 체인          GIWA Sepolia · chainId 91342
 EAS           0x42…21          SchemaRegistry 0x42…20
 결정 스키마    0xba13…f486      resolver 0xcf7e…0fc9
 정산 스키마    0x7ed0…b4f4      resolver 0xdc64…f6c9
 지표          BTC_PRICE_KRW_AT_END
               definitionHash 0xdb9b…7a75
               문서 docs/metrics/BTC_PRICE_KRW_AT_END.md
 · 온체인 definitionHash가 이 문서의 해시와 다르면 verifier가 불일치로 판정합니다.
```

## R1-7 `[P2]` 그 밖

- `#/me`와 `#/passport/<addr>`는 **같은 조회 모델**을 공유한다.
  `/me`는 연결 주소 + "처리 필요", Passport는 임의 주소 읽기 전용.
- `#/verify`는 독립 결과 화면이 아니라 **상세로 보내는 진입점**이다.
- §3의 "상태별 정렬"과 §4.3의 "커밋 시각 내림차순"이 모순이었다 →
  **커밋 시각 내림차순 하나**로 통일. "지금 할 일"은 정렬이 아니라 **필터**다.

## R1-8 홈 대시보드

**긴장**: 통상의 대시보드는 집계 KPI인데 POI는 그것을 금지한다
(`PLAN.md` §3 · W10 · §6.5 Sybil).

**해법**: 집계가 아니라 **개별 증서와 다음 동작**을 보여준다.
홈은 기본적으로 **검증자 대시보드**이고, 지갑을 연결하면 **기록자 받은함**이 아래에 붙는다.

### 지갑 없이 (기본)

```
════════════════════════════════════════════════════════
 POI 판단 증서
 GIWA Sepolia · chainId 91342                     [지갑 연결]
════════════════════════════════════════════════════════
 투자 판단을 내린 시점과 내용을 온체인에 고정하고,
 결과가 나온 뒤 그 판단이 맞았는지 누구나 검증할 수 있게 합니다.
 판단의 결과는 발행자가 아니라 컨트랙트가 산술로 판정합니다.

 ───────────────────────────────────────────────────────
 기록 열기                                    지갑이 필요 없습니다
   decisionUID  [0x…                    ]  [열기]

 ───────────────────────────────────────────────────────
 예시 증서                    ← 배포 환경이면 DEPLOYMENT의 UID, 로컬이면 seed.json
   ▣ 정산완료   0xf6f0…af5e   [보기 →]
   ▣ 정산완료 + 철회 이력      [보기 →]
   ▣ 기한초과   0x755e…edff   [보기 →]
   ▣ 대기                      [보기 →]

 ───────────────────────────────────────────────────────
 최근 열어본 증서              ← localStorage. 없으면 이 절을 그리지 않는다
   0x9eff…7828  ▣정산완료   2분 전에 봄       [보기 →]

 ───────────────────────────────────────────────────────
 ▸ 검증 환경                   ← 접힘
   체인 GIWA Sepolia · 91342 │ 최신 블록 시각 … │ 컨트랙트 배포됨
   스키마 UID 4종 · 지표 2종과 definitionHash
```

### 지갑을 연결하면 아래에 붙는다

```
 ───────────────────────────────────────────────────────
 처리할 기록                                   0xf39F…2266
   ▣ 정산대기   BTC 30일 변동성 판단   구간 종료 2시간 전 지남   [정산하기 →]
   ! ▣ 기한초과  ETH 낙폭 판단          유예 3시간 지남          [보기 →]
   (없으면: "지금 처리할 기록이 없습니다.")

 ───────────────────────────────────────────────────────
 최근 커밋한 기록
   2026-07-28 06:33  ▣정산완료  BTC 가격 판단        [보기 →]
                                                    [내 기록 전체 →]
```

### 규칙

- **어디에도 총 개수·비율·적중률·평균·점수·순위·이의 수를 두지 않는다.**
  각 위젯은 **개별 항목의 나열**이거나 **환경 정보**다.
- 지갑 전용 위젯이 비어 있어도 `기록 열기`를 밀어내거나 잠그지 않는다.
- **자동 연결 요청을 하지 않는다.** 모든 공개 조회는 `publicClient`로.
- `예시 증서`는 배포 환경에서도 있어야 한다 — **`seed.json`이 없으면 심사자가 막힌다.**
  `VITE_EXAMPLE_UIDS`(쉼표 구분)로 주입하고, `docs/DEPLOYMENT.md`의 값을 넣는다.

### 각 위젯이 읽는 것

| 위젯 | 데이터 |
|---|---|
| 기록 열기 | 입력 UID → `getAttestation` · 결정 스키마 확인 |
| 예시 증서 | `VITE_EXAMPLE_UIDS` 또는 `seed.json` → 각 UID의 `deriveState` |
| 최근 열어본 | `localStorage` (UID·마지막 조회 시각) → 각 UID의 현재 상태 |
| 검증 환경 | `CHAIN`·`SCHEMAS`·`isDeployed()`·최신 블록·`METRICS` |
| 처리할 기록 | 연결 주소의 결정 로그 → `activeHead`·`revokeCount`·`getChainTime` → `deriveState` 후 `AWAITING`/`OVERDUE`만 |
| 최근 커밋 | 같은 로그, 커밋 시각 내림차순 상위 몇 건 |

## R1-9 `[P1]` E2E 전환 순서 — 회귀를 숨기지 않는다

codex 지적: 지금 16개는 **한 페이지 전제**이고, 더구나 `seed.json`이 없으면
스펙 전체가 **skip**되어 명령이 성공으로 끝난다. **skip이 통과로 읽힌다.**

### 먼저 고칠 것

- `seed.json`이 없으면 **skip이 아니라 실패**로 만든다.
  시드 없이 도는 E2E는 아무것도 증명하지 않는다.
- Playwright 설정에 `forbidOnly` + **`--max-failures=0`** 그리고
  실행 요약에 `skipped`가 0인지 확인하는 단계를 둔다.

### 전환 순서

```
1  현재 16개의 단언을 "행위 표"로 문서화한다 (무엇을 보장하는지)
2  라우터를 넣되 처음에는 기존 단일 페이지를 그대로 렌더 → 16/16 유지
3  라우터 단위 테스트 + 딥링크·새로고침·뒤로/앞으로·404 E2E를 먼저 추가
4  읽기 경로부터 이동:  #/d/<uid> → #/verify → Passport
   (지갑 없이 상세에 직접 진입하는 테스트를 추가)
5  #/record · #/me 이동. 발행 후 URL이 #/d/<uid>가 되는지 확인
6  full-path를 실제 라우트 이동으로 바꾼다. 기존 단언을 하나도 약화하지 않는다
7  1의 행위 표가 새 테스트로 전부 대응된 뒤에만 단일 페이지 경로를 제거한다
```

**완료 조건은 "16/16"이 아니다.**
→ **기존 16개의 행위 보존 + 라우팅/딥링크 테스트 추가 + skipped 0.**
