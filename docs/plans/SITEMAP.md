# SITEMAP 화면 기획 — 사이트맵과 와이어프레임

## 0. 지금 구조의 문제

한 페이지에 9개 절이 순서 없이 나열돼 있다.

```
지갑 · 저널과 노트 · 결정 커밋 · 정산 · 이의 · 상태 · 결정 DAG · Strategy Passport · 공개
```

**기능은 다 있는데 "누가 무엇을 하러 왔는지"가 없다.** 구체적으로:

| | |
|---|---|
| 1 | 세 종류의 사람(기록자·검증자·이의 제기자)이 한 화면에 섞여 있다 |
| 2 | **하나의 결정을 다루는 정보가 다섯 절에 흩어져** UID를 계속 복사해 붙여야 한다 |
| 3 | 시간이 흐르는 물건인데 **"지금 내가 할 일"이 없다** — 정산할 때가 된 결정을 알 수 없다 |
| 4 | POI가 무엇을 증명하는지 화면에 없다 |
| 5 | 딥링크가 없어 심사자에게 "이 결정을 보라"고 줄 URL이 없다 |

---

## 1. 사용자와 그가 하려는 일

| | 누구 | 하려는 일 | 지갑 |
|---|---|---|---|
| **A** | 기록자 | 판단을 남기고, 때가 되면 정산한다 | 필요 |
| **V** | 검증자 (제3자·심사자) | 남의 기록을 조회하고 대조한다 | **불필요** |
| **B** | 이의 제기자 | 남의 정산에 이의를 단다 | 필요 |

**V가 지갑 없이 전부 할 수 있어야 한다.** 그것이 B10("서버를 신뢰하지 않는다")의 요점이고,
심사자가 가장 먼저 시도할 경로다.

## 2. 시간 축 — 이 제품의 뼈대

```
t0        커밋        결정이 존재했다는 사실이 고정된다
          ↓
windowStart ~ windowEnd   관측 구간 (아무것도 할 수 없다. 기다린다)
          ↓
windowEnd            정산 가능
          ↓
+ graceSeconds       이 선을 넘으면 OVERDUE — 되돌릴 수 없다
```

**화면은 이 축을 따라야 한다.** 지금은 축이 없어서 사용자가 자기가 어디에 있는지 모른다.

## 3. 사이트맵

해시 라우팅(`#/...`)을 쓴다. 정적 배포에서 서버 설정 없이 딥링크와 뒤로가기가 동작한다.
라우터 라이브러리를 도입하지 않는다 — 경로 6개에 50줄이면 충분하다.

```
#/                        홈
                          POI가 무엇을 증명하는지 3줄 + 지금 할 수 있는 일 3갈래
                          지갑 없이 볼 수 있다

#/record                  기록하기                                   [A · 지갑 필요]
                          저널 → 노트 승격 → 결정 커밋 (3단계 진행)

#/me                      내 기록                                    [A · 지갑 필요]
                          내 결정 목록 · 상태별 정렬 · "지금 할 일"

#/d/<decisionUID>         결정 상세                                  [V · 지갑 불필요]
                          ★ 이 앱의 중심. 하나의 결정에 대한 모든 것
                          상태 인장 · 등급 · 평문 필드 · 정산 · 이의 · 공개 · 계보

#/verify                  검증하기                                   [V · 지갑 불필요]
                          UID로 조회 · reveal 대조 · verifier CLI 명령

#/passport/<address>      Strategy Passport                          [V · 지갑 불필요]
                          한 지갑의 기록 나열 (순위 아님)

#/fixtures                데모 데이터                                [개발·시연]
                          seed.json이 있을 때만 메뉴에 나타난다
```

**핵심 변경: `#/d/<uid>`가 중심이 된다.** 지금 상태·DAG·정산·이의·공개로 흩어진 것이
하나의 결정 아래 모인다. UID를 다섯 번 붙여넣을 일이 없어진다.

### 네비게이션

상단 고정. 지갑이 없으면 `기록하기`·`내 기록`은 흐리게(비활성) 두되 **숨기지 않는다** —
무엇이 있는지는 보여주고, 왜 못 쓰는지 알려준다.

```
POI 판단 증서 │ 홈  기록하기  내 기록  검증하기 │ 0xf39F…2266 미검증  [연결]
```

## 4. 와이어프레임

기호: `───` 괘선 · `▣` 인장 · `[버튼]` · `▸` 접힘 · `!` 인주색 경고 · `·` 회색 보조

### 4.1 `#/` 홈

지갑 없이 열리는 첫 화면. **무엇을 증명하는 물건인지**가 먼저다.

```
════════════════════════════════════════════════════════
 POI 판단 증서
 GIWA Sepolia · chainId 91342                     [지갑 연결]
════════════════════════════════════════════════════════

 투자 판단을 내린 시점과 내용을 온체인에 고정하고,
 결과가 나온 뒤 그 판단이 맞았는지 누구나 검증할 수 있게 합니다.
 판단의 결과는 발행자가 아니라 컨트랙트가 산술로 판정합니다.

 ───────────────────────────────────────────────────────
 지금 할 수 있는 일

   판단을 남긴다              남의 기록을 검증한다        이의를 제기한다
   결정을 커밋하고 시점을      UID만 있으면 지갑 없이      정산의 관측값이
   고정합니다                  대조할 수 있습니다          틀렸다고 기록합니다
   [기록하기 →]               [검증하기 →]                · 결정 상세에서

 ───────────────────────────────────────────────────────
 ! 이 앱은 GIWA Sepolia 테스트넷에서 동작합니다. 실제 자산과 무관합니다.

 · 데모 데이터 보기 (seed.json이 있을 때만)
```

세 갈래가 §1의 세 사용자와 1:1이다. **가운데 정렬하지 않고 좌측 정렬**(W-DESIGN).

### 4.2 `#/record` 기록하기 — 3단계

3계층(저널→노트→결정)이 **왜 세 개인지**가 화면에서 보여야 한다.

```
 기록하기
 ───────────────────────────────────────────────────────
  ① 저널        ② 노트         ③ 결정
  검증 안 됨     시점 고정      시점 + 예상 결과 고정
  ●────────────○─────────────○
 ───────────────────────────────────────────────────────

 ① 저널 — 생각을 적어 둡니다
 ! 이 기록은 검증되지 않습니다  (브라우저에만 저장됩니다)

   내용  ┌──────────────────────────────┐
         └──────────────────────────────┘
   [저장]

   · 저장된 저널
     2026-07-28 09:12  "BTC 조정 국면…"      [노트로 승격 →]

 ───────────────────────────────────────────────────────
 ② 노트 — 이 내용이 이 시각에 존재했다는 것만 고정합니다
   (저널에서 승격하거나 바로 작성)
   [노트 발행]  → 발행 후 영수증(UID · 트랜잭션)

 ───────────────────────────────────────────────────────
 ③ 결정 — 예상 결과까지 선언합니다
 · trigger는 온체인에서 강제되지 않습니다
 ! 아래 항목은 평문으로 온체인에 기록됩니다
     predicate · 관측 조건 · 참조

   결정 내용 / trigger / 근거(선택) / 이유(선택)
   ▸ 예상 결과 선언                       ← 접힘. 열면 지표·op·임계·구간
   ▸ 계보 (부모 결정 · 승격 노트)          ← 접힘

   [salt 생성 및 백업]  → 모달 → 백업 확인해야 [발행] 활성
```

- **접힘(`▸`)을 쓴다.** 지금은 15개 필드가 전부 펼쳐져 있어 압도적이다.
  선택 항목은 접고, 필수만 먼저 보인다(progressive disclosure).
- 발행에 성공하면 **`#/d/<uid>`로 이동**한다. 지금은 UID만 남고 끝난다.

### 4.3 `#/me` 내 기록 — "지금 할 일"

```
 내 기록                                   0xf39F…2266
 ───────────────────────────────────────────────────────
 지금 할 일 (2)

  ▣ 정산대기   BTC 30일 변동성 판단        구간 종료 2시간 전 지남
               0x9eff…7828                        [정산하기 →]

  ▣ 기한초과   ETH 낙폭 판단               유예 3시간 지남
               0x755e…edff                        [보기 →]
 ───────────────────────────────────────────────────────
 전체 (5)

  ▣ 정산완료   …                    정산 철회 이력 있음   [보기 →]
  ▣ 대기       …                    구간 시작까지 2시간   [보기 →]
  …
 ───────────────────────────────────────────────────────
 · 조회된 것이 전부라는 보장은 없습니다.
```

- **"지금 할 일"이 맨 위.** `정산대기`·`기한초과`만 올라온다. 이것이 §2 시간 축의 UI다.
- 정렬은 **커밋 시각 내림차순 하나**. 정렬 컨트롤 없음. 점수·순위 없음.
- `기한초과`는 인주색. 되돌릴 수 없다는 것이 보여야 한다.

### 4.4 `#/d/<uid>` 결정 상세 — 이 앱의 중심

**지갑 없이 전부 읽힌다.** 쓰기 동작만 지갑을 요구한다.

```
 ← 내 기록                                      0x9eff…7828  [복사]
 ═══════════════════════════════════════════════════════
                    ┌─────────┐
                    │ 정산완료 │ ▣        상태  정산됨
                    └─────────┘           등급  SELF_DECLARED · SEALED
                                          · 왼쪽은 근거 첨부, 오른쪽은 공개 여부
                    ! 정산 철회 이력 있음
 ═══════════════════════════════════════════════════════
 커밋
   발행자      0xf39F…2266   미검증 지갑
   커밋 시각    2026-07-28 06:33:00 UTC
   검증 스냅샷  0x00…0   · 스냅샷 UID를 찾지 못했습니다
   트랜잭션    0x1234…      (로컬 체인이라 링크 없음)

 예상 결과                                    ← 평문. 온체인에 그대로 있다
   지표        BTC_PRICE_KRW_AT_END
   조건        ≥ 91,201,000
   관측 구간    07-28 06:33 ~ 06:43 UTC
   유예        1시간          → 기한 07-28 07:43 UTC

 ───────────────────────────────────────────────────────
 정산                                          [정산하기]  ← 소유자에게만
   결과        OBSERVED
   관측값       92,201,000    출처 upbit:KRW-BTC:1m
   관측 시각    구간 종료 시각(고정)
   발행        0x5d9a…09c3    트랜잭션 0x…
   · 결과는 관측값으로부터 컨트랙트가 판정합니다. 직접 고를 수 없습니다.

   ▸ 이전 정산 1건 (철회됨)                    ← 접힘. 정정 이력

 ───────────────────────────────────────────────────────
 이의                                          [이의 제기]
 · 조회된 것이 전부라는 보장은 없습니다.
   0xabc…  0x7099…79C8  미검증 지갑  NOT_OBSERVED  출처 other-exchange
   (건수 표시 없음 · 정렬 없음)

 ───────────────────────────────────────────────────────
 공개 (Reveal)
   salt와 payload를 넣으면 이 화면에서 대조합니다. 지갑이 필요 없습니다.
   attester와 commitment는 체인에서 읽습니다 — 손으로 넣을 수 없습니다.
   [대조하기]

 ───────────────────────────────────────────────────────
 계보                                          ▸ 부모 3개 (접힘)

 ───────────────────────────────────────────────────────
 오프체인 검증
   $ poi-verify 0x9eff…7828 --rpc <url> --json      [복사]
   · 이 명령이 업비트에서 값을 다시 가져와 온체인 정산과 대조합니다.
```

**이 화면 하나가 심사자에게 줄 URL이다.** 상태·근거·정산·이의·공개·계보·검증 명령이
한 곳에 있고, 지갑 없이 열린다.

### 4.5 `#/verify` 검증하기 — 지갑 없이

```
 검증하기                          지갑이 필요 없습니다
 ───────────────────────────────────────────────────────
 ① 기록 열기
   decisionUID  [0x…            ]  [열기]

 ② 공개 대조 (salt와 payload를 받았다면)
   → 결정 상세의 "공개"에서 합니다. UID를 넣으면 이동합니다.

 ③ 오프체인 verifier
   $ poi-verify <decisionUID> --rpc <url> --json
   종료코드  0 일치 · 1 불일치 · 2 조회 실패 · 3 검증 못 함
   · verifier는 업비트에서 값을 다시 가져와 온체인 정산과 대조합니다.
     지표 정의는 docs/metrics/ 에 있고 그 문서 해시가 온체인 definitionHash입니다.
```

### 4.7 `#/fixtures` 데모 데이터

`seed.json`이 있을 때만 네비게이션에 나타난다. **데모에서 UID를 복사할 필요가 없어진다.**

```

  F4  기한초과               0x755e…edff   [보기 →]
  F5  대기                   0x6180…b37b   [보기 →]
  복사본  CT18 검증용         0x73c0…da8e   [보기 →]
 ───────────────────────────────────────────────────────
 · 로컬 EAS는 lib v1.4.0입니다. 실제 배포본 검증은 포크 테스트가 담당합니다.
```

## 5. 프로세스별 확인

| 흐름 | 경로 | 막히는 곳이 없는가 |
|---|---|---|
| 판단 남기기 (A) | `#/` → `#/record` → 발행 → `#/d/<uid>` | salt 백업 관문이 ③에 있다. 발행 후 상세로 이동해 결과가 보인다 |
| 정산 (A) | `#/me` "지금 할 일" → `#/d/<uid>` → 정산 | 정산할 때가 된 것이 목록 맨 위에 온다 |
| 검증 (V, 지갑 없음) | `#/` → `#/verify` → `#/d/<uid>` | 전 구간 지갑 불필요. reveal도 상세에서 |
| 이의 (B) | `#/d/<uid>` → 이의 제기 | 대상 정산이 눈앞에 있다 |
| 심사자 | URL 하나(`#/d/<uid>`) | 상태·근거·정산·이의·검증 명령이 한 화면에 |
| 데모 | `#/fixtures` → 각 상태 | UID 복사가 필요 없다 |

## 6. 구현 범위와 원칙

- **디자인 톤은 그대로.** `W-DESIGN.md`의 괘선·인장·미색·인주를 재사용한다. 새 색 금지.
- **로직을 다시 쓰지 않는다.** 기존 컴포넌트를 라우트 아래로 옮겨 재배치하는 것이 대부분이다.
  순수 함수와 그 테스트(63개)는 그대로여야 한다.
- **라우터 라이브러리를 도입하지 않는다.** `web/src/router.tsx`에 해시 라우팅 50줄.
  `hashchange` 리스너 + 경로 파싱. 뒤로가기·딥링크가 동작해야 한다.
- **접힘(`▸`)은 `<details>`로.** JS 없이 접근성이 따라온다.
- 명세의 상시 표시 문구는 §4의 위치에 그대로 둔다. 하나도 빠뜨리지 않는다.
- 건수 표시·정렬·순위 금지 규칙은 그대로.

## 7. E2E에 미치는 영향

기존 16개는 **한 페이지 전제**로 쓰여 있다. 라우팅이 들어가면 선택자가 깨진다.

- E2E를 라우트 기준으로 고친다. **테스트를 지우지 말 것.**
- `fullpath.spec.ts`는 오히려 자연스러워진다 — 실제 사용자 동선과 같아진다.
- 완료 조건은 여전히 **16/16**이다.
