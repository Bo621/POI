# C6 POIChallengeResolver — `poi.challenge.v1`

명세 §5.4 · §6.5 (B8, I15). 이 파일만 읽고 구현할 수 있어야 한다. 명세 문서는 읽지 말 것.

## 파일

- 새로: `contracts/src/POIChallengeResolver.sol`
- 새로: `contracts/test/POIChallengeResolver.t.sol`
- **그 외 파일은 수정 금지.** `POICodec.sol`·`POIResolverBase.sol`은 이미 필요한 것을 전부 제공한다.

## 스키마 (`POICodec.ChallengeData` — 이미 존재한다)

```
bytes32 settlementUID
uint8   claimedResult
bool    hasObservedValue
int128  observedValue
string  source
uint64  observedAt
bytes32 noteCommitment
```

`revocable: true` · `refUID: settlementUID`

## 컨트랙트 구조

`POIResolverBase`를 상속한다 (`POIMetricRegistry`는 상속하지 않는다 — 지표는 Decision 전용).

```solidity
contract POIChallengeResolver is POIResolverBase {
    bytes32 public settlementSchemaUID;

    /// 정산별·발행자별 활성 이의 1건. 철회되면 0으로 돌아가 재발행이 가능해진다 (B8).
    mapping(bytes32 settlementUID => mapping(address challenger => bytes32 challengeUID))
        public activeChallenge;

    constructor(IEAS eas) POIResolverBase(eas) {}

    /// 필요한 UID를 전부 받는 단일 진입점 — 부분 초기화 봉쇄 (§6.2).
    function initialize(bytes32 challengeSchemaUID, bytes32 settlementSchema) external {
        _requireNonZeroUID(settlementSchema);
        settlementSchemaUID = settlementSchema;
        _initializeBase(challengeSchemaUID);
    }
}
```

`onAttest`는 상태를 쓰므로 `view`가 아니다. 시그니처는 C5(`POISettlementResolver.sol`)와 동일하게:
`function onAttest(Attestation calldata a, uint256) internal override ready returns (bool)`

## 강제할 불변식

`_guard(a, schemaUID)`를 가장 먼저 호출한다 — 스키마 일치 · `expirationTime==0` · `recipient==0`이
거기서 처리된다. 그 다음 순서대로:

| # | 조건 | revert할 커스텀 에러 |
|---|---|---|
| 1 | `a.revocable == false` | `MustBeRevocable()` |
| 2 | payload가 정규 인코딩이 아님 | `MalformedPayload()` |
| 3 | `a.refUID != c.settlementUID` | `RefUIDMismatch()` |
| 4 | `c.claimedResult > 2` | `ResultOutOfRange()` |
| 5 | `settlementUID` attestation이 없음 (`uid == 0`) | `SettlementNotFound()` |
| 6 | 그 attestation의 `schema != settlementSchemaUID` | `SettlementWrongSchema()` |
| 7 | 그 attestation의 `revocationTime != 0` | `SettlementRevoked()` |
| 8 | **I15** `activeChallenge[settlementUID][a.attester] != 0` | `AlreadyChallenged()` |

전부 통과하면 `activeChallenge[c.settlementUID][a.attester] = a.uid;` 후 `true` 반환.

### 2번 — payload 정규성 (C3·C4·C5와 같은 규칙)

EAS는 `data`를 스키마에 대해 검증하지 않는다. 잉여 워드나 비정규 offset을 붙여도
`abi.decode`가 조용히 무시해서, 불변식은 다 통과하는데 온체인에는 비정규 payload가 영구히 남는다.
문자열이 있어 길이 검사로는 못 막으므로 **디코딩 결과를 다시 인코딩해 바이트 대조**한다.
C5의 `_requireCanonicalPayload`를 그대로 본떠 쓸 것 (`POISettlementResolver.sol` 참고):

```solidity
bytes memory canonical = abi.encode(
    c.settlementUID, c.claimedResult, c.hasObservedValue,
    c.observedValue, c.source, c.observedAt, c.noteCommitment
);
if (keccak256(data) != keccak256(canonical)) revert MalformedPayload();
```

### `onRevoke` — B8의 핵심

```solidity
function onRevoke(Attestation calldata a, uint256) internal override returns (bool) {
    POICodec.ChallengeData memory c = POICodec.decodeChallenge(a.data);
    if (activeChallenge[c.settlementUID][a.attester] == a.uid) {
        activeChallenge[c.settlementUID][a.attester] = 0;   // ★ 재발행 가능
    }
    return true;
}
```

자기가 활성 이의가 아닐 때는 아무것도 하지 않는다 — 그렇지 않으면 뒤늦은 중복 철회가
현재 활성 이의를 지운다.

## 하지 말 것 (범위 경계)

- `claimedResult`와 `hasObservedValue`의 정합성 검사 **넣지 말 것**. 정산(C5)과 달리 이의는
  온체인 판정 대상이 아니다. 명세에 없다.
- `observedAt`·`source`·`noteCommitment`에 대한 검사 넣지 말 것. 명세에 없다.
- 이의 **건수 카운터를 만들지 말 것** — 명세가 건수 표시를 금지한다(Sybil). 매핑만 둔다.
- 정산 발행자 본인의 자기 이의를 막지 말 것. 명세에 없다.

## 리뷰 대응 R1 — `[P2]` 정규성 테스트가 약하다

변이 테스트 결과: `_requireCanonicalPayload`의 `keccak256` 대조를 **길이 대조**로 약화시켜도
19개가 전부 통과한다. 즉 현재 테스트는 "잉여 바이트"만 잡고 **비정규 인코딩**은 잡지 못한다.
재인코딩 대조를 하는 이유 자체가 검증되지 않는다.

`contracts/test/POIChallengeResolver.t.sol`에 테스트 **하나만** 추가한다. 다른 파일·다른 테스트는 건드리지 말 것.

```
test_Attest_RevertsOnDirtyStringPadding
```

- `_challengeData(_challenge())`로 정규 인코딩을 만든다. `source = "upbit"`(5바이트)이므로
  마지막 워드의 뒤 27바이트는 정규 인코딩에서 0이다. `abi.decode`는 그것을 무시한다.
- 그 패딩 영역의 **마지막 바이트를 0xFF로 바꾼다**. 길이는 그대로다.
- `vm.expectRevert(POIChallengeResolver.MalformedPayload.selector)` 후 `_attest`.

바이트 조작은 `bytes memory`를 직접 인덱싱하면 된다: `data[data.length - 1] = 0xFF;`

검증: `forge test` → 143/143. 그리고 `_requireCanonicalPayload`를 길이 대조로 바꾸면
**이 테스트가 실패해야 한다**(확인 후 원복할 것).
