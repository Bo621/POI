# V1·V2 오프체인 verifier 골격 + 온체인 정산 대조

`verifier/`는 지금 빈 디렉터리다. pnpm 워크스페이스에는 이미 등록돼 있다(`pnpm-workspace.yaml`).

**이 항목이 하는 일**: decisionUID를 받아 온체인 결정·정산을 읽고, `@poi/core`의 순수 함수로
판정을 다시 계산해 **온체인 정산과 대조**한다. 불일치면 비영(非零) 종료코드.

**이 항목이 하지 않는 일**: 지표 관측값을 실제로 가져오는 것. 데이터 출처·간격·결측치 정책은
V3(지표 정의 문서)의 몫이고 사람의 판단이 필요하다. 여기서는 **인터페이스만** 두고 구현은 넣지 않는다.

## 파일

- 새로: `verifier/package.json`
- 새로: `verifier/tsconfig.json`
- 새로: `verifier/src/version.ts`
- 새로: `verifier/src/reader.ts` — 체인 읽기 인터페이스 + viem 구현
- 새로: `verifier/src/metric.ts` — 지표 관측 인터페이스 (**구현 없음**)
- 새로: `verifier/src/verify.ts` — 핵심 로직
- 새로: `verifier/src/cli.ts` — 진입점
- 새로: `verifier/test/verify.test.ts`
- **그 외 파일 수정 금지.** `core/`·`contracts/`·`pnpm-workspace.yaml` 손대지 않는다.

`core/package.json`·`core/tsconfig.json`을 그대로 본떠 쓴다 (`type: module`,
`node --experimental-strip-types --test test/*.test.ts`, viem 의존).
`@poi/core`는 `"dependencies": {"@poi/core": "workspace:*"}`로 참조한다.

## `verifier/src/reader.ts`

네트워크 없이 테스트할 수 있도록 **인터페이스와 구현을 분리**한다.

```ts
export interface OnChainDecision {
    uid: Hex;
    attester: Hex;
    time: bigint;
    revocationTime: bigint;
    hasExpectedOutcome: boolean;
    outcomeMetricId: Hex;
    outcomeOp: number;
    outcomeThreshold: bigint;
    windowStart: bigint;
    windowEnd: bigint;
    graceSeconds: bigint;
    evidenceCommitment: Hex;
}

export interface OnChainSettlement {
    uid: Hex;
    attester: Hex;
    time: bigint;
    revocationTime: bigint;
    result: number;
    hasObservedValue: boolean;
    observedValue: bigint;
    source: string;
    observedAt: bigint;
    verifierVersion: string;
    supersedes: Hex;
}

export interface ChainReader {
    getDecision(uid: Hex): Promise<OnChainDecision | undefined>;
    getActiveHead(decisionUID: Hex): Promise<Hex>;      // 0x00..0 이면 없음
    getRevokeCount(decisionUID: Hex): Promise<number>;
    getSettlement(uid: Hex): Promise<OnChainSettlement | undefined>;
    getMetricDecimals(metricId: Hex): Promise<number>;
}
```

그리고 viem 기반 구현 `createViemReader(config)`를 둔다. 얇게 — `publicClient.readContract`
호출과 `decodeAbiParameters`뿐이다. **단위 테스트하지 않는다**(네트워크가 필요하다).
파일 주석에 "이 구현은 O 단계의 포크 리허설에서 검증한다"고 남긴다.

`attestation.data`는 평면 튜플이다. 디코딩할 때 `decodeAbiParameters`에
스키마 필드 순서를 그대로 나열한다 (구조체로 넘기지 말 것 — 앞에 offset 워드가 붙는다).

## `verifier/src/metric.ts` — 인터페이스만

```ts
export interface Observation {
    /** 스케일 전 원값. 소수 문자열로 받는다 — 부동소수를 거치지 않기 위해서다 */
    raw: string;
    source: string;
    observedAt: bigint;
}

export interface MetricProvider {
    readonly metricId: Hex;
    observe(windowStart: bigint, windowEnd: bigint): Promise<Observation | undefined>;
}

export class MetricRegistry {
    register(p: MetricProvider): void;
    get(metricId: Hex): MetricProvider | undefined;
}
```

**구현체를 하나도 넣지 말 것.** 파일 상단에 남긴다:

> 지표 구현은 V3(지표 정의 문서 6종)이 확정된 뒤에 붙인다. 데이터 출처·간격·UTC 기준·
> 결측치 정책은 문서가 정하고, 문서 해시가 `definitionHash`가 된다. 문서 없는 지표는
> 컨트랙트가 등록을 거부한다(§11.3).

## `verifier/src/verify.ts` — 핵심

```ts
export const VERDICT = {
    MATCH: "MATCH",                      // 온체인 정산이 우리 계산과 일치
    MISMATCH: "MISMATCH",                // 불일치 — 비영 종료코드
    NO_SETTLEMENT: "NO_SETTLEMENT",      // 활성 정산이 없다
    NOT_REQUIRED: "NOT_REQUIRED",        // 결정이 예상 결과를 선언하지 않았다
    NO_OBSERVATION: "NO_OBSERVATION",    // 독립 관측을 얻지 못했다 (지표 미구현 포함)
} as const;

export interface VerifyReport {
    verifierVersion: string;
    decisionUID: Hex;
    verdict: (typeof VERDICT)[keyof typeof VERDICT];
    state: PoiState;                 // core의 deriveState
    hasRevokedSettlement: boolean;
    settlementUID?: Hex;
    onChain?: {result: number; observedValue: bigint | null; observedAt: bigint; source: string};
    independent?: {scaledValue: bigint; expectedResult: number; raw: string; source: string};
    problems: string[];              // 사람이 읽는 한국어 문장들
}

export async function verifyDecision(args: {
    reader: ChainReader;
    metrics?: MetricRegistry;
    decisionUID: Hex;
    now: bigint;
}): Promise<VerifyReport>;
```

### 순서

1. `getDecision`. 없으면 던진다 (`export class VerifyError extends Error {}`).
2. 결정이 철회됐으면 `problems`에 한 줄 추가한다 (판정은 계속한다 — 철회된 결정에
   정산이 남아 있는 것 자체가 알려야 할 사실이다).
3. `getActiveHead` / `getRevokeCount` → `core`의 `deriveState`로 상태를 구한다.
   `activeHead ≠ 0`이면 `getSettlement`으로 `time`을 얻어 넘긴다.
4. `hasExpectedOutcome === false` → `NOT_REQUIRED`로 즉시 반환.
5. 활성 정산이 없으면 `NO_SETTLEMENT`로 반환 (상태는 그대로 담는다 — OVERDUE 여부가 보인다).
6. **온체인 자기정합 검사** — 컨트랙트가 이미 강제하지만, 구현이 바뀌었거나 다른 체인의
   데이터를 볼 수도 있으므로 독립적으로 다시 본다. 어긋나면 `problems`에 넣고 `MISMATCH`:
   - `observedAt !== windowEnd`
   - `hasObservedValue === false && result !== 2`
   - `hasObservedValue === true && result !== settlementResult(...)` (core 사용)
7. **독립 대조** — `metrics`가 없거나 해당 지표 provider가 없으면 `NO_OBSERVATION`.
   있으면 `observe()` → `scale(raw, decimals)` → `settlementResult(...)`:
   - 스케일된 값이 온체인 `observedValue`와 다르면 `MISMATCH` (문장에 두 값을 모두 적는다)
   - 기대 result가 온체인 `result`와 다르면 `MISMATCH`
   - 둘 다 같으면 `MATCH`
8. 6번에서 이미 `MISMATCH`면 7번 결과가 무엇이든 `MISMATCH`를 유지한다.

`scale`·`evalPredicate`·`settlementResult`·`deriveState`·`RESULT`는 **전부 `@poi/core`에서
import**한다. verifier 안에서 다시 구현하지 말 것 — 두 벌이 되면 갈라진다.

## `verifier/src/cli.ts`

```
사용법: poi-verify <decisionUID> [--rpc <url>] [--json]
```

- 종료코드: `0` = MATCH · `NOT_REQUIRED` · `NO_SETTLEMENT` · `NO_OBSERVATION`
- 종료코드 `1` = **MISMATCH**
- 종료코드 `2` = 사용법 오류 · 결정 없음 · 그 밖의 예외
- `--json`이면 리포트를 JSON으로, 아니면 한국어 요약을 출력한다.
- `process.exit`를 `main()` 밖에서만 호출한다 — 테스트가 `verifyDecision`을 직접 부를 수 있게.

`package.json`의 `"bin": {"poi-verify": "./src/cli.ts"}`.

## 테스트 — `verifier/test/verify.test.ts`

`ChainReader`를 구현한 **가짜 리더**를 테스트 안에 만든다. 네트워크를 쓰지 않는다.

| # | 내용 |
|---|---|
| 1 | `VERIFIER_VERSION === "poi-verifier/1.0.0"` |
| 2 | `hasExpectedOutcome=false` → `NOT_REQUIRED` |
| 3 | 활성 정산 없음 + `now ≥ W+G` → `NO_SETTLEMENT`, `state === "OVERDUE"` |
| 4 | 활성 정산 없음 + 철회 이력 있음 → `hasRevokedSettlement === true` (처음부터 정산 안 한 경우와 구별) |
| 5 | 자기정합 정산 + provider 없음 → `NO_OBSERVATION` (MISMATCH가 아니다) |
| 6 | `observedAt !== windowEnd` → `MISMATCH` |
| 7 | `hasObservedValue=false`인데 `result=0` → `MISMATCH` |
| 8 | `result`가 관측값과 반대 → `MISMATCH` |
| 9 | provider가 온체인과 같은 값을 주면 → `MATCH` |
| 10 | provider가 **다른 값**을 주면 → `MISMATCH`, `problems`에 두 값이 모두 들어 있다 |
| 11 | provider 값은 같은데 결과 판정이 다른 경우 → `MISMATCH` |
| 12 | 철회된 결정에 정산이 있으면 `problems`가 비어 있지 않다 |
| 13 | 결정이 없으면 `VerifyError` |
| 14 | 소수 지표: `decimals=2`, `raw="6.005"` → `scale`이 `601n` (core와 같은 half-up) |

## 리뷰 대응 R1 — `[P1]` viem 리더가 타입 체크를 통과하지 못한다

`npx tsc --noEmit` 결과:

```
src/reader.ts(105,15): error TS2322:
  Types of property 'graceSeconds' are incompatible. Type 'number' is not assignable to type 'bigint'.
```

viem의 `decodeAbiParameters`는 **`uint32`·`uint64` 이하를 `number`로, `uint256`·`int128` 등
큰 타입만 `bigint`로** 준다. `OnChainDecision`은 `graceSeconds: bigint`를 요구한다.
단위 테스트는 가짜 리더만 쓰므로 이 경로를 못 잡는다 — 실제 체인을 읽는 순간 깨지는 자리다.

`verifier/src/reader.ts`만 고친다. **인터페이스(`OnChainDecision`)의 타입을 바꾸지 말 것** —
`core`의 `deriveState`가 `bigint`를 받고, 시간·유예를 `number`로 다루면 큰 값에서 정밀도가 깨진다.

디코딩 직후 **명시적으로 `BigInt(...)`로 승격**한다. `graceSeconds`뿐 아니라
`windowStart`·`windowEnd`·`observedAt`·`time`·`revocationTime` 등 **viem이 `number`로 주는
필드 전부**를 확인해 승격할 것. 반대로 `result`·`outcomeOp`처럼 인터페이스가 `number`인 것은
`Number(...)`로 내린다.

승격 지점에 주석을 남긴다: viem은 uint32/uint64를 number로 준다 — 인터페이스 경계에서 한 번만 변환한다.
