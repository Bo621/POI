# X4·X5 core 파생 함수 — scale / eval / result / state

`core/`의 순수 함수 두 묶음. 프론트(W5·W7)와 verifier(V1)가 같은 코드를 쓴다.
**컨트랙트와 결과가 갈리면 안 된다** — 갈리면 정산이 온체인에서 revert하거나,
UI가 온체인과 다른 상태를 보여준다.

## 파일

- 새로: `core/src/evaluate.ts` — X4 (E2·E3·E4·E5)
- 새로: `core/src/state.ts` — X5 (E9)
- 새로: `core/test/evaluate.test.ts`
- 새로: `core/test/state.test.ts`
- 수정: `core/src/index.ts` — `export * from "./evaluate.ts";` 와 `export * from "./state.ts";` 두 줄 추가
- **그 외 파일 수정 금지.** `contracts/` 는 손대지 않는다.

기존 스타일을 맞출 것: `core/src/commitment.ts`(주석 밀도·에러 클래스·명명),
`core/test/commitment.test.ts`(`node:test` + `node:assert/strict`).
주석은 한국어로, **왜 그렇게 했는지**를 쓴다.

# X4 — `core/src/evaluate.ts`

## E2 `scale`

```
scale(x, decimals) = round_half_up( x × 10^decimals )
```

시그니처: `export function scale(x: number | string, decimals: number): bigint`

- 반환은 **`bigint`**다. 컨트랙트의 `int128`과 대응한다. `number`로 두면 큰 값에서
  정밀도가 조용히 깨진다.
- 입력 `x`는 소수 문자열(`"0.15"`, `"-2.5"`)도 받는다. **부동소수 연산을 쓰지 말 것** —
  `0.1 * 10` 같은 계산이 `1.0000000000000002`가 되어 반올림 경계에서 틀린다.
  문자열을 정수부/소수부로 쪼개 자릿수 이동으로 처리한다.
- `number`로 들어온 경우도 일단 문자열로 바꿔 같은 경로를 탄다.
  단 `Number.isFinite`가 false면 던진다.
- **half-up**은 "절댓값 기준 0.5 이상이면 절댓값이 커지는 쪽으로". 즉
  `scale("2.5", 0) === 3n`, `scale("-2.5", 0) === -3n`.
  (JS `Math.round`는 `-2.5 → -2`다. 그대로 쓰면 음수에서 틀린다.)
- `decimals`가 음의 정수이거나 정수가 아니면 던진다. 상한은 18로 둔다.
- `int128` 범위를 벗어나면 던진다 (`-(2^127) … 2^127 - 1`). 컨트랙트가 받을 수 없는
  값을 조용히 만들지 않는다.

에러는 `export class EvaluateError extends Error {}` 하나로 통일한다.

## E3·E4 `evalPredicate`

```
export const OP = {GT: 0, GTE: 1, LT: 2, LTE: 3, EQ: 4, NEQ: 5} as const;
export type Op = (typeof OP)[keyof typeof OP];

export function evalPredicate(op: Op, scaledValue: bigint, threshold: bigint): boolean
```

`POISettlementResolver._eval`과 **정확히 같은 표**:

| op | 의미 | 결과 |
|---|---|---|
| 0 | GT | `v > t` |
| 1 | GTE | `v >= t` |
| 2 | LT | `v < t` |
| 3 | LTE | `v <= t` |
| 4 | EQ | `v == t` |
| 5 | NEQ | `v != t` |

범위 밖 `op`는 던진다 (컨트랙트는 5 초과를 `OpOutOfRange`로 막지만, 여기서는
`else`로 흘려보내면 NEQ가 되어 조용히 다른 답이 나온다).

## E5 `settlementResult`

```
export const RESULT = {OBSERVED: 0, NOT_OBSERVED: 1, INDETERMINATE: 2} as const;
export type Result = (typeof RESULT)[keyof typeof RESULT];

export function settlementResult(args: {
    hasObservedValue: boolean;
    scaledValue?: bigint;      // hasObservedValue = true일 때 필수
    op: Op;
    threshold: bigint;
}): Result
```

- `hasObservedValue === false` → `INDETERMINATE`
- `true`인데 `scaledValue`가 `undefined` → 던진다 (조용히 INDETERMINATE로 떨어지면
  컨트랙트의 `MustBeIndeterminate`/`ResultMismatch`와 어긋난다)
- 그 외: `evalPredicate` 결과가 참이면 `OBSERVED`, 거짓이면 `NOT_OBSERVED`

| `settlementResult` | 관측값 없음 → INDETERMINATE · 참 → OBSERVED · 거짓 → NOT_OBSERVED · `hasObservedValue=true`인데 값 없음 → throw |
| **컨트랙트 대조** | 아래 참조 |

### 컨트랙트 대조 — 이 항목의 핵심

`contracts/test/POISettlementResolver.t.sol`의 `test_Eval_MatchesSpecForAllOpsAtBoundary`가
임계 600, 관측값 599/600/601로 op 6종의 기대 result를 이미 고정해 뒀다.
**같은 표를 TS 테스트에도 둔다**: op 6종 × {599n, 600n, 601n} → 기대 result.

| op | 599 | 600 | 601 |
|---|---|---|---|
| GT(0) | 1 | 1 | 0 |
| GTE(1) | 1 | 0 | 0 |
| LT(2) | 0 | 1 | 1 |
| LTE(3) | 0 | 0 | 1 |
| EQ(4) | 1 | 0 | 1 |
| NEQ(5) | 0 | 1 | 0 |

(0 = OBSERVED, 1 = NOT_OBSERVED)

주석에 "이 표는 `contracts/test/POISettlementResolver.t.sol`의 같은 표와 일치해야 한다"고
남긴다. 한쪽만 고치면 정산이 온체인에서 `ResultMismatch`로 튕긴다.

# X5 — `core/src/state.ts`

## E9 `deriveState`

```
export const STATE = {
    NOT_REQUIRED: "NOT_REQUIRED",
    SETTLED: "SETTLED",
    SETTLED_LATE: "SETTLED_LATE",
    PENDING: "PENDING",
    OBSERVING: "OBSERVING",
    AWAITING: "AWAITING",
    OVERDUE: "OVERDUE",
} as const;
export type PoiState = (typeof STATE)[keyof typeof STATE];

export interface StateInput {
    hasExpectedOutcome: boolean;
    windowStart: bigint;      // S0
    windowEnd: bigint;        // W
    graceSeconds: bigint;     // G
    activeHead: `0x${string}`;   // 0x00..0 이면 정산 없음
    activeHeadTime?: bigint;     // activeHead != 0 일 때 필수
    revokeCount: number;
}

export interface StateOutput {
    state: PoiState;
    /** revokeCount > 0 이면 true. UI가 「정산 철회 이력 있음」을 병기한다 */
    hasRevokedSettlement: boolean;
}

export function deriveState(input: StateInput, now: bigint): StateOutput
```

판정 순서는 명세 그대로:

```
NOT_REQUIRED   ¬hasExpectedOutcome
SETTLED        activeHead ≠ 0 ∧ activeHeadTime <  W+G
SETTLED_LATE   activeHead ≠ 0 ∧ activeHeadTime ≥ W+G
PENDING        activeHead = 0 ∧ now <  S0
OBSERVING      activeHead = 0 ∧ S0 ≤ now <  W
AWAITING       activeHead = 0 ∧ W  ≤ now <  W+G
OVERDUE        activeHead = 0 ∧ now ≥ W+G
```

- `activeHead ≠ 0`인데 `activeHeadTime`이 없으면 던진다 (`export class StateError extends Error {}`).
  SETTLED와 SETTLED_LATE를 가르는 유일한 입력이므로 추측하면 안 된다.
- `hasRevokedSettlement`는 상태와 **독립**이다. `OVERDUE + 철회 이력 있음`이
  "처음부터 정산하지 않음"과 구별되는 지점이다.
- `hasExpectedOutcome === false`면 나머지 필드를 보지 않는다.

## 테스트 — `core/test/state.test.ts`

| 묶음 | 내용 |
|---|---|
| NOT_REQUIRED | `hasExpectedOutcome=false`면 다른 필드가 무엇이든 NOT_REQUIRED |
| 경계 `t = S0` | `now = S0 - 1n` → PENDING · `now = S0` → OBSERVING |
| **경계 `t = W`** | `now = W - 1n` → OBSERVING · `now = W` → AWAITING |
| **경계 `t = W+G`** | `now = W+G-1n` → AWAITING · `now = W+G` → OVERDUE |
| SETTLED 경계 | `activeHeadTime = W+G-1n` → SETTLED · `= W+G` → SETTLED_LATE |
| 정산이 상태를 덮는다 | `now`가 아무리 커도 `activeHead ≠ 0`이면 OVERDUE가 아니다 |
| 철회 이력 | `revokeCount = 1` + `activeHead = 0` + `now ≥ W+G` → `OVERDUE` + `hasRevokedSettlement = true`. **`revokeCount = 0`인 OVERDUE와 구별된다** |
| 거부 | `activeHead ≠ 0`인데 `activeHeadTime` 없음 → throw |

## 하지 말 것

- `Date.now()`를 함수 안에서 부르지 말 것. `now`는 인자다 — 그래야 테스트가 결정적이다.
- 온체인 조회 코드(viem 호출)를 넣지 말 것. 이 파일들은 **순수 함수**다.
- `number`로 시간이나 임계값을 다루지 말 것. 전부 `bigint`.
- 명세 문서(`docs/POI_*.md`)를 읽지 말 것.
