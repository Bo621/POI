---

## 2 — 문제

# 투자에서 남는 건 거래 기록이지 **판단**이 아니다

거래는 거래소에 남는다. 수익률도 남는다.
**그런데 "왜 그렇게 판단했는가"는 아무 데도 남지 않는다.**

그래서 결과를 본 뒤에 이렇게 말할 수 있다.

> "나는 그럴 줄 알았다."

이걸 반증할 방법이 지금은 없다.

---

## 3 — 왜 안 풀렸나

# 기록은 언제든 고쳐 쓸 수 있다

| | |
|---|---|
| 트레이딩 저널 | 사후 수정 가능 |
| 리더보드·카피트레이딩 | 성과만 보고 판단은 안 본다 |
| SNS 예측 | 지우면 그만 |

**시점을 위조할 수 없게 만드는 것**이 문제의 전부다.
그리고 그건 체인이 원래 잘하는 일이다.

---

## 4 — 해법

# 결과를 알기 전에 잠근다

```
t0                          t1              t2
결정 커밋                  관측 구간 종료      결과 등록
─────────────────────────────────────────────────────
내용은 해시로만            관측값 확정      컨트랙트가 판정
관측 구간을 미리 선언                       발행자가 아니라
                                          컨트랙트가 계산
```

**세 가지가 온체인에서 강제된다.**

1. 관측 구간을 **과거로 잡을 수 없다**
2. 정산 결과를 **발행자가 정할 수 없다**
3. 결정은 **철회할 수 없다** (정산과 이의는 정정 가능)

---

## 5 — 핵심 방어 ①

# 관측 구간을 과거로 설정할 수 없다

```solidity
if (d.windowStart < attestTime) revert WindowInPast();   // I4
```

결과를 보고 나서 "그 구간을 보고 있었다"고 주장하는 순간
**트랜잭션이 되돌아간다.**

> 데모 fixture를 만들다가 실제로 여기 걸렸다.
> 우회하지 않고 새 구간을 열었다 — 이걸 뚫으면 제품이 사라진다.

---

## 6 — 핵심 방어 ②

# 정산 결과를 발행자가 정할 수 없다

발행자가 제출하는 것은 **관측값과 출처뿐이다.**

```solidity
uint8 expect = _eval(d.outcomeOp, s.observedValue, d.outcomeThreshold) ? 0 : 1;
if (s.result != expect) revert ResultMismatch();   // I17
```

관측값과 모순되는 결과를 기록하는 것이 **불가능하다.**

---

## 7 — 핵심 방어 ③

# 기준을 나중에 바꿀 수 없다

지표마다 **계산식·데이터 출처·간격·결측치 정책** 문서가 있고,
그 **문서 바이트의 해시**가 온체인에 박혀 있다.

```bash
cast keccak "$(cat docs/metrics/BTC_PRICE_KRW_AT_END.md)"
# → 온체인 definitionHash 와 동일
```

등록 즉시 `frozen`. **문서 없는 지표는 컨트랙트가 등록을 거부한다.**

---

## 8 — 왜 GIWA인가 (1)

# 비용이 시점 해상도를 정한다

```
                커밋 1건       결정 커밋 36건/년
GIWA            0.53원              19원
이더리움 L1    5,040원         181,000원
```

약 **9,500배**

*(120,000 gas · ETH $3,000/1,400원 · L1 10 gwei 가정)*

---

## 9 — 왜 GIWA인가 (2)

# 고비용 체인에서 남는 선택지는 둘, 둘 다 POI를 깎는다

| | 절감 | 잃는 것 |
|---|---|---|
| 트랜잭션 묶기 | **17%뿐** | **결정 간 선후 관계** (I2 · EAS 배치는 timestamp가 같다) |
| 집계 커밋 하나로 | 큼 | 개별 결정 UID → **정산·이의가 붙을 곳이 없다** |

POI는 저비용 체인 위에서 *더 싼* 제품이 아니라,
저비용 체인이라야 **해상도가 유지되는** 제품이다.

---

## 10 — 왜 GIWA인가 (3)

# 새 신뢰 축을 세우지 않는다

POI의 앵커는 새 레지스트리가 아니라 **EAS SchemaResolver**다.

```
사용자 → EAS.attest() → [POI 리졸버가 불변식 검사] → 기록
```

| 쓰는 것 | |
|---|---|
| **EAS 프리디플로이** | 스키마·발급·철회·참조를 재구현하지 않는다 |
| **도장 Verified Address** | KYC 결속 온체인 신원 |
| **저비용 L2** | 결정 단위 커밋의 경제성 |

GIWA 생태계에 **편입**된다.

---

## 11 — 지금 살아 있는 것

# 테스트넷에서 전 경로가 돈다

| | |
|---|---|
| 컨트랙트 | 리졸버 4종 — **익스플로러 Verified** |
| 스키마 | EAS 4종 등록·초기화 |
| 지표 | 2종 등록, 문서 해시로 **frozen** |
| 화면 | 커밋 → 결과 등록 → 이의 → 공개 검증 |
| 검증기 | `poi-verify` · `poi-reveal` CLI |
| 테스트 | **384개** (contracts 150 · core 62 · verifier 58 · web 87 · e2e 27) |

**심사자가 지갑 없이 직접 확인할 수 있다.**

---

## 12 — 데모

# 네 가지 상태가 동시에 살아 있다

| | 보여주는 것 |
|---|---|
| 등록완료 + 이의 | 제3자가 관측값에 이의를 걸었다 |
| 철회 이력 | 정산을 철회하고 정정했다 — 그 이력이 남는다 |
| 기한초과 | **미발행이 드러난다** |
| 터미널 `MATCH` | 오프체인에서 독립 재현 |

**미발행을 숨기지 않는 것**이 이 제품의 태도다.

---

## 13 — 하지 않는 것

# 랭킹을 만들지 않는다

~~성과 랭킹~~ ~~리더보드~~ ~~수익률 공개~~ ~~카피트레이딩~~
~~종목 추천~~ ~~자동매매~~ ~~판단 품질 점수~~

배지 개수도 사실상 점수로 작동하므로 **개수 정렬·비교 UI를 금지**한다.

> "누가 더 잘하는가"가 아니라
> **"이 판단이 언제 있었고 무엇을 말했는가"만 다룬다.**

## 15 — 한계 (숨기지 않는다)

# 아직 독립 판정이 아니다

| | |
|---|---|
