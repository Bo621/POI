## 2 — 한 장으로 보는 POI

# 판단을 **결과가 나오기 전에** 잠근다

투자 판단 하나를 온체인에 고정하고, 구간이 끝나면 **발행자가 낸 관측값과 결과가 어긋나지 못하게**
컨트랙트가 산술로 강제한다. *(관측값 자체의 진실성은 보장하지 않는다 — 4장 신뢰 경계)*

| | | |
|---|---|---|
| **STEP 01** 판단을 적고 잠근다 | 내용은 해시로만 올린다. 무엇을 볼지(지표·조건·관측 구간)는 이때 **미리** 선언한다 | “BTC 가 이 10분 구간 끝에 **9,100만 원**을 넘는다” |
| **STEP 02** 구간이 끝난다 | 선언해 둔 구간이 지나면 관측값이 확정된다. 업비트 공개 1분봉이라 누구나 같은 값을 다시 구할 수 있다 | 관측값 **91,998,000 원** · 출처 `upbit-1m-candles` |
| **STEP 03** 컨트랙트가 판정한다 | 발행자는 관측값만 낸다. 맞았는지는 컨트랙트가 다시 계산해 대조하고, 어긋나면 **거래를 되돌린다** | 결과 **맞음** — 발행자가 정할 수 없다 (I17) |

> **이 예시는 지금 체인에 있는 실제 기록이다.** 결정 `0x5941a398…443888` · 정산 `0x9ae6d320…65fa52`

## 3 — 문제

# 남는 건 거래 기록이지 **판단**이 아니다

거래는 거래소에 남고 수익률도 남는다.
**"왜 그렇게 판단했는가"는 아무 데도 남지 않는다.**

그래서 결과를 본 뒤에 이렇게 말할 수 있다.

> "나는 그럴 줄 알았다."

기존 수단은 전부 **사후 수정이 가능**하다 — 트레이딩 저널, SNS 예측, 리더보드.
지우거나 고치면 그만이다.

제도권 리서치를 떠난 투자자가 유튜버·뉴스레터로 옮겨갔다.
그런데 **거기서 한 말이 맞았는지 확인할 방법이 없다.**

| | |
|---|---|
| 6,300건 | 유사투자자문 관련 민원 (2017.03~2025.08) · 금융감독원 |
| 975건 | **미등록 투자자문** — 분모는 분류 가능분 6,101건 (16%) |
| 1.7% | 신고 **포상금 지급률** (104건 · 7,610만원) |
| 1,022만 | 가상자산 투자자 수 · 보유 69.9조 원 (2026.02, 5대 거래소 제출자료) |

**규제는 이미 들어왔다. 전부 사후 단속이다.** 2024.08 자본시장법 개정으로 양방향 유료
리딩방은 등록 투자자문업자만 운영할 수 있고, 2025.10 금감원은 해외주식 리딩방에
소비자경보 「주의」를 냈다. **사전에 판단을 고정시키는 장치는 어디에도 없다.**

> **출처** 금융감독원 유사투자자문 민원 집계 · 머니투데이 2025.10.27 「신고 포상률 1.7%」 ·
> 금융위원회 가상자산 실태조사 · 금감원 2025.10.29 소비자경보

## 5 — 사용자 ★

# 리서치를 쓰는 사람에게 **무엇이 달라지는가**

유료 뉴스레터를 운영하는 **A**. 구독자는 “이 사람 말이 맞았나”를 묻고, A 는 증명할 방법이 없다.
*(실제 사용자가 아닌 가상 시나리오다.)*

| 지금 | POI 이후 |
|---|---|
| 3월에 “반도체 조정 온다”고 썼다. **맞았다.** 그런데 구독자에게 보여줄 게 지난 메일 캡처뿐이다 | 발행 전에 판단을 커밋한다. **내용은 해시로만 올라가** 미리 스포일러가 되지 않는다 |
| 경쟁자는 틀린 회차를 조용히 지운다. **지운 사람과 안 지운 사람이 화면에서 구별되지 않는다** | 구간이 끝나면 결과를 등록한다. **안 올리면 「기한초과」로 남는다** — 골라 기록하는 것이 드러난다 |
| 새 구독자는 결국 “요즘 잘 맞힌다더라”는 **평판**으로 고른다 | 구독자에게 **링크 하나**를 준다. 제3자가 직접 대조하고, 틀렸다고 보면 **이의를 온체인에 남긴다** |

> **왜 이게 가능한 문제인가** — 자본시장연구원은 투자의견이 “주관적 기준에 따른 정성적
> 정보라 **사후적인 검증이나 비교가 매우 어렵다**”고 지적한다. 검증을 어렵게 만드는 것은
> 데이터가 아니라 **판단이 결과 이후에 수정 가능하다는 구조**다.

# 결과를 알기 전에 잠근다

```
t0                     t1                  t2
결정 커밋              관측 구간 종료         결과 등록
──────────────────────────────────────────────────
내용은 해시로만        관측값 확정          컨트랙트가 판정
관측 구간 선언                             발행자가 아니라
                                          컨트랙트가 계산
```

**결정은 철회할 수 없다.** 정산과 이의는 정정할 수 있고, 그 이력이 남는다.

## 4 — 신뢰 경계 ★

# 무엇을 보장하고 무엇을 보장하지 않는가

| | |
|---|---|
| 컨트랙트가 강제 | 관측 구간이 커밋 이후다 · 정산 산술이 관측값과 일치한다 · 결정 간 선후 관계 · 지표 정의가 고정돼 있다 |
| 소유자가 제출 | 관측값 자체 (제3자가 재현·이의 가능) |
| 보장하지 않음 | 관측값의 진실성 · 이유의 진실성 · 실제 거래와의 정합성 · **기록의 완전성** |

> POI가 온체인에 남기는 **원문**은 네 개의 commitment(결정·트리거·근거·이유)다.
> 관측 조건(`metricId`·`op`·`threshold`)과 구간은 **평문으로** 남는다. 그 시점에 그 commitment가
> 기록됐다는 것이 보장되고, **공개(Reveal) 이후에** 제공된 원문이 그 commitment의
> 프리이미지임을 누구나 확인할 수 있다.
>
> 공개 전에는 "무언가가 고정됐다"까지, 공개 후에는 "이 내용이 그때 고정됐다"까지다.

## 5 — 컨트랙트가 강제하는 것

# 세 줄의 코드가 사후 서사를 막는다

```solidity
if (d.windowStart < attestTime) revert WindowInPast();          // I4
if (p.time >= a.time)           revert ParentNotEarlier();      // I2
if (s.result != expect)         revert ResultMismatch();        // I17
```

| | |
|---|---|
| I4 | 관측 구간을 과거로 못 잡는다 *(예상 결과를 선언한 결정에 적용)* |
| I2 | 부모 결정이 자식보다 엄격히 빨라야 한다 |
| I17 | 관측값과 모순되는 결과를 기록할 수 없다 *(산술 일치만 — 관측값의 진실성은 별개)* |

그리고 **지표 정의 문서의 바이트 해시**가 온체인에 박혀 등록 즉시 `frozen`이다.
기준을 나중에 바꿀 수 없다.

## 6 — 왜 GIWA인가 ①

# 비용이 시점 해상도를 정한다

```
                 커밋 1건        결정 커밋 36건/년
GIWA             1.21원              44원
이더리움 L1     850원           30,600원
```

약 **702배**

> **전부 실측이다** — 실제 발행한 트랜잭션의 gas 424,275, GIWA 가스 가격 0.001 gwei,
> 이더리움 가스 가격 0.734 gwei, 업비트 ETH 2,731,000원 (2026-07-29 22:24 KST).
> 다만 **L1 가스 가격은 혼잡도에 따라 수십 배 움직인다** — 배수는 그때의 값이다.

비용을 줄이려 배치하면 **같은 배치 안의 부모→자식 관계가 끊긴다**(I2 · EAS 배치는
timestamp가 같다). 절감은 기본가스뿐이라 약 17%에 그친다.

## 7 — 왜 GIWA인가 ②

# 새 신뢰 축을 세우지 않는다

POI의 앵커는 새 레지스트리가 아니라 **EAS SchemaResolver**다.

```
사용자 → EAS.attest() → [POI 리졸버가 불변식 검사] → 기록
```

| 쓰는 것 | |
|---|---|
| EAS 프리디플로이 | *Ethereum Attestation Service — 「누가 무엇을 언제 증명했다」를 기록하는 표준. GIWA 에 기본 탑재.* 스키마·발급·철회·참조를 재구현하지 않는다 |
| 도장 Verified Address | *도장 = GIWA 의 온체인 신원 인증.* 「누가 말했는가」의 근거. 연동 완료 — 발급자 라벨(UPBIT KOREA / TESTNET FAUCET)까지 구별한다. **받아 본 것은 파우셋 발급분이고 KYC 경로는 미검증** |
| 저비용 L2 | 결정 단위 커밋의 경제성 |

GIWA 생태계에 **편입**된다.

## 8 — 경쟁 ★

# 진짜 대안은 "EAS로 직접 만드는 것"

| | 인간지표 *(국내)* | TipRanks *(해외)* | EAS 직접 구축 | POI |
|---|---|---|---|---|
| 방식 | 제3자 관찰 | 제3자 관찰 | — | **본인이 사전 고정** |
| 기준을 누가 정하나 | 관찰자 *(발언일 +1거래일 종가)* | 관찰자 | 설계자 | **본인이 커밋 전에** |
| 누가 들어가나 | 관찰자가 고른 19명 | 추적 가능한 매체만 | — | **누구나** |
| 관측 구간 소급 차단 | ✗ | ✗ | 직접 설계해야 | ✓ `I4` |
| 판정 주체 | 운영자 | 운영자 | 설계자 | **컨트랙트** `I17` |
| 미발행 노출 · 이의 | ✗ | ✗ | 직접 설계해야 | ✓ |
| 성과 랭킹 | ✓ 핵심 | ✓ 핵심 | 자유 | **✗ 의도적 배제** |

**카테고리는 이미 검증됐다.** TipRanks 는 전문가 96,000명+ 를 2009년부터 추적하고,
국내에도 인간지표가 경제 유튜버 19명·668건을 검증한다. 수요는 실재한다.

다만 둘 다 **밖에서 관찰**한다. 그래서 대상이 관찰자가 고른 사람으로 제한되고,
**기준을 대상자가 동의한 적이 없고**, 서비스가 문을 닫으면 기록도 사라진다.
인간지표는 스스로 결과가 *「가상·재미」*라고 밝힌다.

> **EAS로 직접 만들면 이 전부를 구현할 수 있다.** 불가능한 게 아니다.
> 차별점은 기술 장벽이 아니라 **어떤 불변식을 고르고 무엇을 금지했는가**다.

만들지 않은 것이 만든 것만큼 중요하다 — 랭킹·점수·비교를 넣는 순간
사후 서사를 막는다는 목적 자체가 무너진다. 그 규율이 제품이다.

## 12 — 실제 화면 ① ★

# 미발행이 **그대로 드러난다**

예상 결과를 선언해 놓고 결과를 올리지 않으면 인장이 **「기한초과」**로 바뀐다. 숨길 자리가 없다.

기한초과 결정 상세(`0x3f592f21…e16938`)의 실제 캡처를 싣고 네 곳을 가리킨다.

1. **인장이 상태를 말한다** — 결과를 안 올린 판단은 「기한초과」로 남는다
2. 누가 말했는지가 붙는다 — 도장 검증 「TESTNET FAUCET」과 검증 스냅샷 UID
3. 커밋 당시 선언한 것이 그대로 — 지표·조건·관측 구간이 커밋 시각과 함께
4. 화면이 검증 명령을 준다 — `poi-verify` 를 복사해 돌리면 MATCH

## 13 — 실제 화면 ② ★

# 제3자가 **이의를 온체인에** 남긴다

실제 이의 1건(`0x655fc265…75d6ee`)의 캡처.

1. **이의자는 정산자와 다른 주소다** — 검증 지갑 여부도 함께 표시(「미검증 지갑」)
2. 관측값과 출처를 같이 남긴다 — `90,688,000 · upbit-1m-candles(재계산)`
3. 건수를 세지 않는다 — 지갑 생성 비용이 0 이라 개수는 부풀릴 수 있다
4. 화면이 먼저 한계를 말한다 — 「조회된 것이 전부라는 보장은 없습니다」

## 14 — 가장 큰 반론 ★

# "좋은 판단만 골라 기록하면?"

**맞다. 완전성은 보장되지 않는다.** 조회된 것이 전부라는 보장도 없다.

그래서 이렇게 대응한다.

| | |
|---|---|
| 미발행을 드러낸다 | 예상 결과를 선언하고 결과를 안 올리면 「기한초과」로 남는다 |
| 건수를 세지 않는다 | 지갑 생성 비용이 0이라 개수는 언제든 부풀릴 수 있다 |
| 목록에 명시한다 | 「조회된 것이 전부라는 보장은 없습니다」 |
| 비교·랭킹을 만들지 않는다 | 선택 기록으로 순위를 만들면 거짓말이 된다 |

**한 지갑 안에서의 선택적 기록은 남는다.** 지금 구조로 못 푼다.
**2단계**의 실행 정합성 검증이 이 문제를 좁힌다.

## 15 — 여기서 무엇이 열리나 ★

# 거래소를 붙이면 **마지막 칸이 닫힌다**

지금 검증되는 것은 **“무엇을 말했나”**까지다. 남은 칸은 **“말한 대로 했나”** —
슬라이드 6에서 *보장하지 않는다*고 적은 바로 그 칸이다.

| 레이어 | 지금 | 거래소를 붙이면 |
|---|---|---|
| ① 말한 것 — 결정 커밋 <br><span>commitment · 관측 구간 선언 · I4</span> | **✔ 검증됨** | 그대로 |
| ② 본 것 — 관측·정산 <br><span>지표 해시 frozen · I17 산술 강제</span> | **✔ 검증됨** | 오라클이 관측값을 독립 증명 |
| ③ 한 것 — 실제 체결 <br><span>지금은 비어 있다</span> | ✕ 보장 안 함 | **체결 내역 대조로 채워진다** |

③ 이 닫히면 **「좋은 판단만 골라 기록한다」**는 반론도 같이 좁혀진다 —
거래가 있었는데 결정이 없으면 그것도 드러나기 때문이다.

> **지금은 가설이다.** 개인 거래내역에 접근할 권한이 없다 — 지금 쓰는 것은
> 업비트 **공개 시세 API** 뿐이다. 거래소 Open API 읽기 권한이 열려야 성립한다.

## 18 — 타겟 · 시장 ★

# 누구를 위해 만들었나

**모수** — 가상자산 투자자 1,022만 명 · 업비트 누적 회원 1,326만 명
(업비트 20·30대 548만 명 = 2030 인구의 44%)

**문제가 실재한다는 증거는 규제다.** 2024.08 자본시장법 강화로 양방향 유료 리딩방은
등록 투자자문업자만 운영할 수 있게 됐고, 2025.10 금감원이 유튜버와 협력해 피해 예방
캠페인을 시작했다. **대응은 전부 사후 단속이다.**

**왜 이 순서인가** — 판단을 파는 쪽이 먼저다. 이들에게는 검증이 비용이 아니라 **무기**다.
읽는 쪽은 그 다음이다. 검증된 판단이 쌓여야 고를 것이 생긴다.
기관은 마지막이다. 조회 API(3단계)가 있어야 발행물에 붙는다.

| | 누구 | 무엇 |
|---|---|---|
| **1차** 지금 | 뉴스레터·리서치 작성자 · 투자 유튜버 · 자문업자 | 이미 사후 검증 압력을 받고 있고, **자기를 구별할 반박 수단이 없다** |
| **2차** 3단계 | 유료 구독자 · 커뮤니티 | 「그때 뭐라고 했는지」를 **링크 하나로 직접 확인한다** |
| **3차** 확장 | 리서치 기관 · 운용사 · RWA 발행사 | 발행물에 **검증 링크를 붙인다.** 사람마다 서류를 다시 받지 않는다 |

> **출처** — 가상자산 투자자 수: 5대 거래소가 의원실에 제출한 자료(2025) ·
> 업비트 회원·연령 분포: 두나무 공시 · 자본시장법 개정(2024.08) · 금감원 캠페인(2025.10)

## 19 — 목표 비즈니스 모델

# 증명을 *확인하는 쪽*이 낸다

```
판단을 남긴다        →   온체인에 쌓인다        →   확인하는 쪽이 낸다
건당 1.21원              누구나 읽을 수 있는          구독자 · 기관 · 발행사
사실상 무료               자산
```

공급을 무료로 열어 두는 것이 전략이다 — 쌓이지 않으면 팔 것 자체가 없다.

| | 누가 내는가 | 무엇에 |
|---|---|---|
| **B2C 구독** | 판단을 읽는 쪽 | 저널 · 장기 리포트 · 외부 공유 프로필 *(3단계)* |
| **검증 수수료** | 제3자가 요청 | 정기 재검증 · 갱신 · 이의 대응 *(3단계)* |
| **B2B 조회 API** | 리서치 기관 · 운용사 | 발행물에 검증 링크를 붙인다. 건당 과금 *(3단계)* |
| **증명 인프라** | RWA 발행사 · 금융기관 | 투자자 증명을 검증한다. **개인정보를 직접 보관하지 않아도 된다** *(확장 · 20쪽)* |

**지금 단계에서 수익화하지 않는다.** 온체인 비용이 건당 **1.21원**(실측)이라 남기는 쪽
부담이 사실상 없다. 단가는 아직 정하지 않았다 — *먼저 확인할 것은 판단이 쌓이는가*이고,
그 기준은 **17쪽 게이트**에 수치로 적어 두었다.
