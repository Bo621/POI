## 막고 있는 것 셋

### 1. 프로젝트 링크 — 공개 호스팅이 없다 ★

문항 8은 **작동하는 MVP URL 또는 시연 영상**을 요구한다.
지금 프론트는 `localhost:4173`에서만 돈다. **이대로는 제출할 수 없다.**

정적 SPA(백엔드 없음, 해시 라우팅)라 배포 자체는 간단하다.
`web/dist`를 그대로 올리면 된다 — Vercel · Netlify · GitHub Pages 중 아무거나.

> 영상(O8 녹화)으로 대체할 수도 있지만, **살아 있는 URL이 훨씬 강하다.**
> 심사자가 직접 눌러보고 온체인 데이터를 확인할 수 있다.

### 2. 피치덱이 없다 ★

문항 7은 필수다. 지금 있는 것은 전부 기술 문서고, 슬라이드가 없다.

기획서에서 뽑아낼 재료는 충분하다 — 문제 정의, §2.1 명제표, §12 경쟁 구도,
§12.2 왜 GIWA인가, §8.2 비용 산식, 로드맵. **재료가 아니라 형식이 없다.**

### 3. 팀 소개 — 제가 쓸 수 없다

이름·역할·국적·경력은 사용자만 압니다.

## 심사 기준 중 우리가 다루지 않은 것

Phase 1 기준 6개 중 **하나가 설계에 반영돼 있지 않다.**

> **06 GIWA 월렛 내 탑재 가능성** — 「월렛에 자연스럽게 담기는 구조」

지금까지 이 각도를 한 번도 고려하지 않았다. 다만 **구조적으로는 유리하다:**

| | |
|---|---|
| 백엔드가 없다 | 정적 SPA + RPC 직접 호출. 서버 의존이 0 |
| 해시 라우팅 | 라우터 라이브러리 없이 `#/d/<uid>` — 임베드 환경에서 깨지지 않는다 |
| EIP-1193만 요구 | 지갑이 제공하는 표준 인터페이스 하나면 동작 |
| 읽기가 대부분 | 지갑 연결 없이도 조회·검증이 된다 |
| 트랜잭션이 가볍다 | 건당 약 0.53원, 서명 1회 |

**월렛 안에서 "내 판단 기록"을 보고, 결정 하나를 커밋하고, 결과를 등록하는 흐름이
그대로 들어간다.** 지원서에 이 논거를 명시적으로 써야 한다 — 지금 문서 어디에도 없다.
