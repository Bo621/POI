# 심사자 시나리오

> **심사자가 실제로 하는 행동**을 순서대로 적고, 각 단계에서 무엇이 보여야 하는지와
> 어긋났을 때 확인할 지점을 함께 둔다.
>
> 지갑이 필요한 것은 S6~S8 뿐이다. **S1~S5 는 지갑 없이 5분 안에 끝난다.**


## S1 — 링크를 열었다 (지갑 없음)

**기대**: 무엇을 하는 제품인지 3줄로 읽힌다. 지갑을 요구하지 않는다.

```
투자 판단을 내린 시점과 내용을 온체인에 고정합니다.
결과가 나온 뒤 그 판단이 맞았는지 누구나 검증할 수 있습니다.
판단의 결과는 발행자가 아니라 컨트랙트가 산술로 판정합니다.
```

nav 오른쪽에 `· 91342` 가 보인다. **집계 숫자·비율·적중률은 어디에도 없다.**

> 어긋나면: `VITE_RPC_URL` 과 `VITE_*_RESOLVER` 가 테스트넷을 가리키는지,
> 개발자도구 Network 에 `127.0.0.1` 요청이 없는지 확인한다.

## S2 — 예시 증서를 눌러 본다

**기대**: 세 건이 서로 다른 상태로 보인다.

| 인장 | UID | 무엇을 보여주나 |
|---|---|---|
| 🔴 기한초과 | `0x06ccb34d…545ebe` | **미발행이 드러난다** |
| 🔵 등록완료 | `0x061ac961…591a69` | 결과 등록 + **제3자 이의** |
| 🔵 등록완료 | `0x8516ac86…56ba21` | **결과 등록 철회 이력 있음** |

상세에서 확인할 것:

- `커밋` — 발행자 주소가 링크다. 누르면 그 지갑의 다른 판단으로 간다
- `예상 결과` — 조건이 `> 1`, 관측 구간이 UTC 로 명시
- `결과 등록` — 관측값 `92602000`, 출처 `upbit-1m-candles`
- `이의` — 이의자가 **정산자와 다른 주소**(`0xca89C0F2…Af5c`)
- 목록마다 「조회된 것이 전부라는 보장은 없습니다」

> 어긋나면: `getLogs` 블록 범위(`VITE_DEPLOY_BLOCK`)와 스키마 UID 를 확인한다.

## S3 — 오프체인으로 재현한다

```bash
git clone https://github.com/Bo621/POI.git && cd POI && pnpm install

export POI_RPC_URL=https://sepolia-rpc.giwa.io/
export POI_EAS_ADDRESS=0x4200000000000000000000000000000000000021
export POI_SETTLEMENT_RESOLVER_ADDRESS=0xbc386addcd3cabbbb62dfcb521939fe4610029d1
export POI_METRIC_REGISTRY_ADDRESS=0x7f784bdba6fa0b5437d6809c28a00125c8ab1b66

node --experimental-strip-types verifier/src/cli.ts \
  0x061ac961bb031dfb9436478f92c898e64bb600871d0f461c394a00b0aa591a69 --json
```

**기대**: `"verdict": "MATCH"` · 종료코드 `0`.

검증기는 온체인 정산을 읽고 **업비트 공개 1분봉으로 관측값을 다시 계산해** 대조한다.

> 종료코드 `3` 이 나오면 관측 구간이 아직 업비트에서 조회되지 않는 것이다 —
> 틀린 것과 검증하지 못한 것은 다르다.

## S4 — 기준이 고정돼 있는지 본다

```bash
cast call 0x7f784bdba6fa0b5437d6809c28a00125c8ab1b66 \
  "metrics(bytes32)(bool,uint8,uint8,bytes32,bool)" \
  0x83b04966e07f0f83592e71060b3356d716b4dff9f824bd76d0f9d149c54cafcf \
  --rpc-url https://sepolia-rpc.giwa.io/

# 파일 **원본 바이트**의 해시다. `$(cat …)` 는 끝 개행을 지워 다른 값이 나온다.
cast keccak "0x$(xxd -p -c 999999 < docs/metrics/BTC_PRICE_KRW_AT_END.md | tr -d '\n')"
```

**기대**: 네 번째 값(`definitionHash`)과 `cast keccak` 결과가 **같다.**
마지막 값이 `true` — `frozen` 이라 정의를 바꿀 수 없다.

> 이것이 "나중에 유리하게 기준을 바꾸는 것"을 막는 장치다.

## S6 — 직접 결정을 커밋한다

`기록하기` → 저널 저장 → 노트 승격 → 결정 폼.

**기대**:
- 단계 표시가 ① → ② → ③ 로 진행
- **salt 백업을 확인하기 전에는 발행 버튼이 비활성**
- 발행 후 결정 상세로 자동 이동, 인장이 「대기」 또는 「관측중」

> salt 를 잃으면 **공개(Reveal)가 영구 불가**하다. 그래서 백업 확인을 강제한다.

## S7 — 과거 구간으로 커밋을 시도한다 ★

**이 시나리오가 POI 의 주장을 검증한다.**

결정 폼의 `관측 시작`을 **지금보다 과거**로 넣고 발행한다.

**기대**: 트랜잭션이 되돌아가고 한국어 오류가 뜬다.

```
관측 구간이 과거입니다 (WindowInPast)
```

컨트랙트가 이렇게 강제한다.

```solidity
if (d.windowStart < attestTime) revert WindowInPast();   // I4
```

**결과를 본 뒤에 "그 구간을 보고 있었다"고 주장할 수 없다.**
이것이 사후 서사를 막는 실제 메커니즘이고, 나머지 주장은 전부 여기에 얹혀 있다.

> 개발 중 데모 fixture 를 만들다가 실제로 여기 걸렸다.
> 우회하지 않고 새 구간을 열었다 — 이 불변식을 데모 편의로 뚫으면 제품이 사라진다.

## S8 — 남의 결정에 결과를 등록해 본다

예시 증서 중 하나를 열고 `결과 등록` 절을 본다.

**기대**: 「결정 작성자만 결과를 등록할 수 있습니다.」 가 보이고 발행할 수 없다.

> 정산 권한을 누구에게나 열면 **그리핑 공격**이 성립한다 —
> 공격자가 임의 결과로 선점 → 소유자는 발행 불가 → 공격자가 철회 →
> 상태가 「기한초과」로 되돌아감 → 무한 반복. 비용은 가스비뿐이다.

## S9 — 복사 공격을 시도한다 (선택)

A 의 결정에서 `공개` 절을 열고, **다른 결정**의 `(salt, payload)` 를 넣어 본다.

**기대**: 불일치. 다운로드 버튼이 비활성.

commitment 프리이미지에 **attester** 가 들어가므로, 남의 commitment 를 복사해
커밋해도 원래 소유자의 `(salt, payload)` 로는 검증되지 않는다.

**검증 도구는 attester 를 입력받지 않는다** — 온체인에서 읽는다.
입력받게 만들면 공격자가 원래 attester 를 타이핑해 거짓 일치를 만들 수 있다.

**S7 은 두 층에서 확인했다.** 화면은 「관측 구간 시작은 발행 시점 이후여야 합니다」로
막아 가스를 쓰지 않고, 클라이언트를 우회해 직접 트랜잭션을 만들면
GIWA Sepolia 의 실제 컨트랙트가 `[Revert] WindowInPast()` 를 낸다.

### 이 실행이 찾아낸 것

- **S4 명령이 틀려 있었다.** `cast keccak "$(cat …)"` 는 끝 개행을 지워
  온체인 값과 다른 해시를 낸다. 심사자가 시키는 대로 했으면 실패했을 것이다.
- 지갑 연결 시 **nav 가 본문 제목을 가렸다**(측정: 실제 180px vs 상수 68px).
- **새로고침하면 연결이 풀렸고**, 연결 해제가 없었으며,
  **지갑에서 계정을 바꿔도 앱이 몰랐다** — 화면은 A 를 보여주고 서명은 B 가 한다.

넷 다 단위 테스트가 통과하는 동안 살아 있었다.

## 이 문서가 지키려는 것

**"검증 가능하다"고 쓰는 것과 검증 가능한 것은 다르다.**

위 아홉 중 하나라도 실행해서 실패하면 그건 결함이다.
실제로 개발 중 화면을 눈으로 보다가 조건 기호 6개가 전부 잘못 표시되던 것을 발견했고,
지갑을 연결하고서야 nav 가 본문 제목을 가리는 것을 발견했다.
**단위 테스트가 통과하는 동안 둘 다 살아 있었다.**
