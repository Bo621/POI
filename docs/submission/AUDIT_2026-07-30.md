문항 8 의 심사자가 저장소를 열면 백서·피치덱과 다른 제품명을 보고 있었다.

그래서 후보는 `P… of I…` 안에서만 나왔다 (`Insight` · `Inference` · `Intent` · `Investing`).
`Inference` 가 가장 엄밀하지만(질도 실행도 함의하지 않음) 「투자 판단」이라는 제품 언어와

`POI_v0.4`~`v0.9` 와 `TechSpec_v2` 는 **그 이름으로 쓰인 이력 문서라 그대로 둔다.**

### B1. 심사자가 복사해 실행하면 **깨지는 명령** (3개 파일 동일)

`reveal-cli` 명령 한가운데에 설명문과 새 코드 펜스가 끼어들어 **명령이 두 조각으로 쪼개졌다.**

- `docs/submission/VERIFY.md:105`
- `gitbook/intro/verify-in-5-min.md:104`  ← **공개된 백서 (문항 10)**
- `gitbook/verify/cli.md:22`  ← **공개된 백서**

```
  --salt 0x0f1e2d3c4b5a69788796a5b4c3d2e1f0 \
  > **`--payload` 는 JSON 이다.** …          ← 여기서 명령이 끊긴다
```
```bash
--payload <(printf …) \                      ← 이건 그냥 안 돈다
```

**고칠 것**: 설명문을 코드블록 밖으로 빼고 한 명령으로 합친다.

또한 `DEPLOYMENT.md:213` 은 `POI_EAS_ADDRESS` 만 필요하다고 하지만
**`POI_DECISION_SCHEMA_UID` 도 필수다.** 없으면 즉시 에러:

```
POI_DECISION_SCHEMA_UID 환경 변수가 올바른 32바이트 UID 가 아니다.
```
둘 다 넣으면 `판정: MATCH` 로 정상 동작한다 (확인함).
