# 심사 채점 — Phase 1 + Phase 2

> **공고 기준 그대로 채점했다.** `giwa.io/gasok` 을 받아 읽어 확인한 8개 기준이다.
> Phase 3 기준(UI/UX 완성도 · 초기 사용자 확보 · 장기 지속 가능성)은 **감점에 쓰지 않았다** —
> 이 제출은 MVP·테스트넷 단계다.
>
> 클로드와 코덱스가 **각자 독립으로** 매기고 대조했다. 2026-07-30.

## 기준별 — 클로드

### 01 GIWA 체인 적합성 — 9

**근거**
- §12.2 가 「왜 다른 체인이면 안 되는가」를 **구조로** 답한다. 비용을 줄이려는 두 갈래가
  각각 무엇을 깨뜨리는지 밝힌다 — 트랜잭션 묶기는 EAS 배치가 같은 timestamp 를 넣어
  **결정 간 선후 관계(I2)를 잃고**, 집계 커밋은 개별 UID 가 사라져 정산·이의가 붙을 곳이 없다.
- EAS 프리디플로이 위에 얹혀 자체 레지스트리를 만들지 않았다. 포크 테스트가 **실제 EAS
  바이트코드**를 상대로 돈다.
- **도장 결합이 온체인으로 증명된다.** `verifiedSchemaUID = 0x072d75e1…6e08`,
  발급자 집합에 `UPBIT KOREA` · `TESTNET FAUCET` 이 라벨과 함께 등록돼 있고,
  검증 지갑으로 발행한 결정(`0x3f592f21…6938`)의 payload 에 스냅샷 UID 가 박혀 있다.

**감점 −1**
- 지금 붙은 검증은 **테스트넷 파우셋**이지 업비트 KYC 가 아니다. 업비트 발급자도 등록해
  뒀지만 일반 사용자가 그 검증을 받는 공개 경로가 없다(GIWA 문서에도 안내가 없다).
  「KYC 결속 신원」은 여전히 미증명이다.

### 02 독창성 — 8

**근거**
- 「관측 구간을 과거로 못 잡는다(I4)」 + 「정산 산술을 컨트랙트가 재계산한다(I17)」 +
  「지표 정의를 문서 바이트 해시로 고정한다」 셋의 조합.
- **안 만든 것이 만든 것만큼 중요하다** — 미발행을 「기한초과」로 드러내고, 이의 건수를
  세지 않고, 랭킹을 만들지 않는다. 「선택 기록으로 순위를 만들면 거짓말이 된다」는 이유가 문서에 있다.

**감점 −2**
- 개별 요소는 전부 기존 기술이다. EAS 로 직접 만들면 구현 가능하고 문서도 그렇게 인정한다.
- 진짜 신규성은 도메인 스키마 설계에 있는데 **심사자가 알아보기 어렵다.**

### 03 실현 가능성 — 10

**근거**
- 테스트넷에 배포돼 **지금 동작한다.** 컨트랙트 4종 익스플로러 독립 검증
  (`is_verified=true`, twin 없음), fixture 5종이 살아 있고 공개 URL 에서 지갑 없이 조회된다.
- 일반 사용자 지갑(메타마스크)으로 커밋 → 정산 → `poi-verify MATCH` 까지 **실제로 돌렸다.**
- 「만들 수 있다」가 아니라 **「만들었다」**를 심사자가 5분 안에 직접 확인한다.

### 04 시장성 — 7

**근거** ([MARKET.md](MARKET.md))
- 가상자산 투자자 1,022만 명 · 업비트 누적 1,326만 명 · 업비트 20·30대 548만 명(2030 인구의 44%)
- **문제가 실재한다는 증거가 규제다** — 2024.08 자본시장법 강화로 유료 리딩방이 불법이 됐고,
  2025.10 금감원이 유튜버와 협력해 피해 예방 캠페인을 시작했다. 대응은 전부 **사후 단속**이다.
- TipRanks 가 같은 문제에서 출발해 Nasdaq·E*TRADE 제휴까지 갔다. 카테고리는 검증됐다.
- 반증 가능한 30일 실험이 있다 — 「10명 × 3건, 절반 이상이 결과를 등록하는가」.
  **등록률이 낮으면 설계가 틀린 것**이라고 먼저 적었다.

**감점 −3**
- 수요 근거가 **전부 2차 자료**다. 인터뷰·대기자·LOI 가 없다.
- **핵심 채택 가설이 미검증이다** — 콘텐츠 작성자가 「결과 전 커밋」과 「미발행 노출」을
  실제로 받아들이는지. 이건 그들에게 불리한 제약이다.
- 수익 가설이 전부 미검증이고 법률 검토 게이트가 열려 있다.

### 05 팀 구성 역량 — 8

**근거**
- 1인이 컨트랙트·프론트·검증기·문서·배포를 완주했고 **결과물이 온체인에 있다.**
- 경력이 문제와 정확히 맞물린다 — 펀드 기준가 산출, 운용 성과 정산 0→1,
  NFT 낙찰 대금 분배·원장 대사, 거래소 FDS. 10년을 프로토콜로 옮긴 것이다.

**감점 −2**
- **1인이다.** 5개월 프로그램을 혼자 가는 건 위험하고 백엔드는 「합류 예정」으로 확정되지 않았다.
- 심사자는 버스 팩터를 본다.

### 06 월렛 내 탑재 가능성 — 7 *(코덱스 6)*

**근거 — 「담길 수 있다」가 아니라 「왜 여기여야 하는가」**

판단에는 재료가 둘 있고 **둘 다 지갑 안에 있다.** 밖에서는 사용자에게 물어봐야 하고,
물어보는 순간 「본인이 원할 때만, 유리한 것만」이 된다 — **POI 가 막으려는 것이 정확히 그것이다.**

| 재료 | 어디에 | 상태 |
|---|---|---|
| 누가 말했는가 | 도장 Verified Address | **연동 완료** — 컨트랙트가 스키마·발급자 검증 |
| 무엇을 들고 있었는가 | 도장 Verified Balance | 스키마가 온체인에 실재. POI 는 아직 안 씀 |

**도장에 이미 프라이버시 원시가 있다** — 보자기를 기다릴 필요가 없다.
`Balance Root`(머클 루트) + `Verified Balance`(`balance, salt, proofs`)로
**잔고를 밝히지 않고 보유를 증명**한다. 온체인에서 직접 읽어 확인했다.

POI 의 술어 `metricId · op · threshold` 와 머클 증명, ZK 술어는 **같은 모양**이다 —
셋 다 「값을 다 보여주지 않고 조건이 참임을 보인다」. 그래서 보자기가 공개되면
**결정 스키마를 바꾸지 않고** `evidenceCommitment` 자리에 넣을 수 있다.

- 기술 조건: 백엔드 없음 · 해시 라우팅 · EIP-1193 만 요구 · 조회는 지갑 없이 동작 ·
  커밋 1건 1.21원(실측) · 서명 1회 · EIP-6963 다중 지갑 탐지

**코덱스와 1점 차이 나는 이유 — 코덱스 지적을 고쳤다**
> 코덱스: 「컨트랙트는 두 발급자를 허용하는데 프런트는 `DOJANG_ISSUER` **한 주소만** 통과시킨다.
> 따라서 faucet 검증을 UI 가 자동으로 붙이지 못한다.」
>
> **맞는 지적이었다.** 프론트가 발급자를 하드코딩하면 온체인 허용 집합과 갈라진다.
> `readIssuerAllowed()` 로 **컨트랙트에 직접 묻도록** 고쳤고 회귀 테스트를 붙였다.
> 채점 시점에는 없던 수정이다.

**감점 −3**
- **검증된 적이 없다.** 월렛 manifest · SDK adapter · 임베드 harness 가 없다.
  **규격을 모르는 채 만들면 추측이 코드가 된다** — 그래서 만들지 않았고, 그 사실을 적었다.
- Verified Balance 를 **아직 쓰지 않았다.** 구조가 맞는다는 것과 붙여 봤다는 것은 다르다.
- 보자기는 여전히 **개발자 문서가 없다** (`/giwa-ecosystem/bojagi` 404, 생태계 목록에도 없음 — 2026-07-30 확인).
- 번들 502KB — 임베드 환경에서 가벼운 편이 아니다.

### 07 실제 구현 수준 — 10 *(코덱스 9)*

**근거**
- fixture **5종**이 테스트넷에 동시에 살아 있다: 기한초과 · 등록완료+제3자 이의 ·
  철회→정정 · **노트 승격 부모** · **부모를 잇는 자식**.
- 오프체인 검증기가 업비트 공개 1분봉으로 관측값을 재계산해 온체인과 대조한다(`MATCH`).
- 메타마스크로 전 경로를 돌렸고 **막아야 할 것이 실제로 막혔다** —
  I4(소급 차단) · I19(provenance 필수) · CT18(사본 위조 탐지) · salt 백업 강제.

**코덱스와 1점 차이 나는 이유**
> 코덱스 채점 시점에는 **Decision Graph fixture 가 없었다.** 「노트→결정 승격과 그래프가
> 구현·배포됐는데 화면에서 볼 수 없다」가 오래된 감점 요인이었고, 채점 뒤에 만들었다.
> 부모 `promotedFromNote` = 노트 UID, 자식 `refUID` = `parents[0]` = 부모 UID 를
> 온체인 디코딩으로 확인했다.

### 08 기술 완성도 — 8

**근거**
- 불변식 I1~I19 중 15개가 코드에 번호 주석으로 표시되고, 포크 테스트가 **실제 EAS 바이트코드** 상대로 돈다.
- commitment 테스트 벡터를 Solidity 와 TS 가 **같은 파일**(`core/vectors/commitment.v1.json`)에서
  읽어, 구현이 갈라지면 테스트가 먼저 깨진다.
- 소유권이 **2-of-2 Safe** 에 있다(`owner = 0x215253B8…DCE1`, `pendingOwner = 0`).
  배포 지갑 단독 `addMetric` 은 `OwnableUnauthorizedAccount` 로 되돌아간다 — 확인했다.
- 새 방어를 넣을 때마다 **뮤테이션으로 검증**했다 — 검사를 지우면 그 테스트가 깨진다.
- 테스트 423, 그리고 **`run_all_tests.sh` 가 실제 게이트다**(실패 시 종료코드 1).

**감점 −2**
- **외부 리뷰 3라운드에서 매번 실제 결함이 나왔다.** 도장 스키마 미검증, provenance 우회,
  **길이를 유지한 offset 변조**(정규 인코딩 우회) — 마지막 것은 재배포까지 필요했다.
  테스트 개수가 품질을 보증하지 못한다는 증거다.
- 지표가 2종뿐이다. `sealRegistry()` 는 넣었지만 호출하지 않았다(Phase 1 지표 추가 필요).
- 두 Safe 키를 **같은 사람이 보유**한다 — 단일 키 위험 제거이지 권한 분산이 아니다.

## 두 심사가 모두 「선발한다」

**클로드**: Phase 2 기준(07 · 08)에서 상위권이다. 말이 아니라 **동작하는 것**을 가져왔고
심사자가 5분 안에 확인한다. GIWA 적합성 논거도 「싸다」가 아니라 구조적이며,
도장 결합이 **온체인 기록으로** 증명된다.

**코덱스**: 「테스트넷에서 실제로 동작하고, 불변식이 코드로 강제되며, 검증 경로가 재현 가능하다.」

## 떨어뜨린다면 — 두 심사가 공통으로 꼽은 것

1. **핵심 채택 가설이 미검증** — 콘텐츠 작성자가 자신에게 불리한 제약을 받아들일 이유가 가설뿐이다
2. **1인 팀** — 5개월을 혼자 가는 위험
3. **월렛 탑재가 미검증** — GIWA 가 이 기준을 중요하게 보면 우리가 만들 수단이 적다

## 코덱스 지적 중 고친 것

| 지적 | 처리 |
|---|---|
| 프런트가 발급자를 하드코딩해 온체인 집합과 갈라진다 | **고침** — `readIssuerAllowed()` 로 컨트랙트에 묻는다. 회귀 테스트 추가 |
| `run_all_tests.sh` 가 파이프 때문에 실패를 삼킨다 | **고침** — 실행/필터 분리, 실패 시 종료코드 1. 일부러 깨뜨려 확인 |
| 문서와 온체인이 갈라지는 것을 사람이 막고 있다 | **고침** — `check_docs_onchain.sh` 추가. 구 UID 4건을 실제로 잡아냈다 |

## 고치지 않은 것 — 이유와 함께

| 제안 | 왜 안 했나 |
|---|---|
| 월렛 임베드 harness · SDK adapter | **월렛 임베드 규격을 모른다.** 규격 없이 만들면 추측이 코드가 된다 |
| 업비트 KYC 검증 획득 | 일반 사용자용 공개 발급 경로가 **없다**(GIWA 문서 확인). 우리가 열 수 없다 |
| 사용자 인터뷰·LOI | 하루로 되는 일이 아니다. Phase 3 에서 할 일이다 |
