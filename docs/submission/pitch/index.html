// 04 사용자

리서치를 쓰는 사람에게 무엇이 달라지는가

유료 뉴스레터를 운영하는 A. 구독자는 “이 사람 말이 맞았나”를 묻고, A 는 증명할 방법이 없다. — 실제 사용자가 아닌 가상 시나리오다.

지금

3월에 “반도체 조정 온다”고 썼다. 맞았다. 그런데 구독자에게 보여줄 게 지난 메일 캡처뿐이다.

경쟁자는 틀린 회차를 조용히 지운다. 지운 사람과 안 지운 사람이 화면에서 구별되지 않는다.

새 구독자는 결국 “요즘 잘 맞힌다더라”는 평판으로 고른다.

POI 이후

발행 전에 판단을 커밋한다. 내용은 해시로만 올라가 미리 스포일러가 되지 않는다.

구간이 끝나면 결과를 등록한다. 안 올리면 「기한초과」로 남는다 — 골라 기록하는 것이 화면에 드러난다.

구독자에게 링크 하나를 준다. 제3자가 직접 대조하고, 틀렸다고 보면 이의를 온체인에 남긴다.

왜 이게 가능한 문제인가 — 자본시장연구원은 투자의견이 “주관적 기준에 따른 정성적 정보라 사후적인 검증이나 비교가 매우 어렵다”고 지적한다. 검증을 어렵게 만드는 것은 데이터가 아니라 판단을 결과 뒤에 고칠 수 있는 구조다.

// 08 왜 GIWA인가 ①

비용이 시점 해상도를 정한다

비용을 줄이려 커밋을 묶어도 절감은 기본가스뿐이라 약 17%에 그친다. 그리고 묶는 순간 같은 배치 안의 결정 선후 관계를 잃는다 — EAS(Ethereum Attestation Service — GIWA 에 기본 탑재된 증명 기록 표준)는 한 배치에 담긴 기록에 모두 같은 시각을 넣기 때문이다.

// 09 왜 GIWA인가 ②

새 신뢰 축을 세우지 않는다

EAS 프리디플로이Ethereum Attestation Service — 증명 기록 표준. GIWA 기본 탑재
스키마·발급·철회·참조를 재구현하지 않는다

「누가 말했는가」의 근거 — 연동 완료. 받아 본 것은 파우셋 발급분, KYC 경로는 미검증

「그때 무엇을 들고 있었나」의 근거 (미사용 · 잔고 값은 공개)

판단의 재료가 지갑에 있다. 누가 말했는가는 연동했고, 무엇을 들고 있었는가는 Verified Balance 로 붙는다. POI 가 조건을 적는 방식(지표 · 부등호 · 기준값)이 영지식 증명의 조건식과 같은 모양이라, 보자기가 공개되면 술어를 숨기는 경로가 열린다 — 증명 검증 설계는 따로 필요하다.

// 15 여기서 무엇이 열리나

거래소를 붙이면 마지막 칸이 닫힌다

지금 검증되는 것은 “무엇을 말했나”까지다. 남은 칸은 “말한 대로 했나” — 앞서 보장하지 않는다고 적은 바로 그 칸이다.

지금은 가설이다. 개인 거래내역에 접근할 권한이 없다 — 지금 쓰는 것은 업비트 공개 시세 API 뿐이다. 거래소 Open API 읽기 권한이 열려야 성립한다.

용어 — up.id GIWA 의 온체인 아이디 · 보자기 GIWA 의 영지식 증명 기술 · ORACLE_VERIFIED 관측값을 제3자 오라클이 독립 증명했을 때 붙는 등급(아직 없음) · ZK 술어 값을 밝히지 않고 「조건을 만족한다」만 증명하는 방식

문제가 실재한다는 증거는 규제다. 2024.08 자본시장법 강화로 양방향 유료 리딩방은 등록 투자자문업자만 운영할 수 있게 됐고, 2025.10 금감원이 유튜버와 협력해 피해 예방 캠페인을 시작했다. 대응은 전부 사후 단속이다.

왜 이 순서인가

판단을 파는 쪽이 먼저다. 이들에게는 검증이 비용이 아니라 무기다 — 아무나 할 수 없는 주장을 할 수 있게 된다.

읽는 쪽은 그 다음이다. 검증된 판단이 쌓여야 고를 것이 생긴다. 공급이 먼저 서는 시장이다.

기관은 마지막이다. 조회 API(3단계)가 있어야 발행물에 붙는다.
