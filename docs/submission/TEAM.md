## 왜 이 사람이 이 문제를 푸는가

POI 는 **"정산을 발행자가 주장하지 못하게 하고, 기준을 나중에 못 바꾸게 한다"** 는
제품입니다. 이 두 문장이 제 커리어 전부입니다.

| 해온 일 | POI 에서 |
|---|---|
| **펀드 기준가 · 지수 산출 로직** 설계 (KG제로인 · 알케미랩) | 지표 정의를 문서로 고정하고 그 **바이트 해시를 온체인에** 박는다 |
| **운용 성과 정산 · PnL 검수 시스템 0→1** (비씨랩스) | 정산 산술을 **컨트랙트가 재계산해 대조**한다 (I17) |
| **낙찰 대금 분배 · 원장 대사** 설계 (빗썸라이브) | 온체인 확정 트랜잭션을 원천으로 삼는 구조를 그대로 옮겼다 |
| **거래소 FDS · 이상거래 탐지** 0→1 (피어테크) | 그리핑 · Sybil 이의 · 복사 공격을 설계 단계에서 막았다 |
| **Upbit 운영 지원** (코네) | GIWA · 도장 생태계의 운영 맥락을 안다 |

정산과 원장 정합성을 **제품으로 만들어 온 사람**이 그것을 프로토콜로 옮긴 것이 POI 입니다.

## 1 인이 어떻게 여기까지 만들었나

**AI 개발 체계를 제품처럼 운영합니다.** POI 도 같은 방식으로 만들었습니다.

```
기획   PRD · 화면설계서 · 수용기준을 먼저 문서로 확정
구현   Claude Code
리뷰   Codex 로 교차 검증 — 구현자와 리뷰어를 분리한다
검증   테스트를 게이트로 두고, 통과하지 못하면 병합하지 않는다
```

POI 개발 중 이 체계가 실제로 잡아낸 것들:

- 화면의 조건 기호 6 개가 전부 잘못 표시되던 것 (`op=1` 은 `≥` 인데 `≠`)
- 지표 해시 대조 명령이 틀려 심사자가 실행하면 실패했을 것
- 지갑을 둘 이상 설치하면 `window.ethereum` 을 한쪽이 가로채 세션 복원이 깨지던 것

**셋 다 단위 테스트가 통과하는 동안 살아 있었습니다.** 테스트가 아니라
실행과 교차 리뷰가 잡았고, 그 과정을 저장소에 기록으로 남겼습니다.
